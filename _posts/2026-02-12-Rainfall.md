# Introduction :

Memory corruption vulnerabilities occur when a program incorrectly handles data writes, allowing an attacker to overwrite critical sections of system memory. When exploited on the call stack, an attacker can overwrite the return instruction pointer (EIP/RIP), seizing control of the program's execution flow.

# Project goals :

Rainfall is a 1337 project that deepens the concepts introduced in Snowcrash. The focus shifts entirely to binary exploitation on a 32-bit architecture. You must analyze vulnerable C binaries, identify flaws such as buffer overflows and format string vulnerabilities, and craft specific exploits to execute shellcode or Return-Oriented Programming (ROP) chains.

# Walkthrough :

:one: Setup and Disassembly :

Upon accessing a level, utilize GDB to disassemble the target binary. Identifying vulnerable functions (like `strcpy`, `gets`, `printf`) is the first step.

    gdb ./level0
    (gdb) set disassembly-flavor intel
    (gdb) disassemble main

:two: Analyzing Stack Frames for Buffer Overflows :

Determine the offset required to overwrite the instruction pointer. Provide a cyclic pattern as input, observe the segmentation fault, and read the value in the EIP register to calculate the exact buffer size.

    (gdb) run $(python -c 'print "A" * 100')

:three: Crafting and Injecting Shellcode :

Once the offset to EIP is calculated, inject shellcode (machine code designed to execute a shell, typically `execve("/bin/sh")`) into the buffer or an environment variable. Modify the EIP payload to point to the memory address where the shellcode resides.

    export EGG=$(python -c 'print "\x31\xc0\x50\x68\x2f\x2f\x73\x68\x68\x2f\x62\x69\x6e\x89\xe3\x50\x53\x89\xe1\xb0\x0b\xcd\x80"')

:four: Exploiting Format String Vulnerabilities :

If user input is passed directly to `printf` without a format specifier (e.g., `printf(user_input)` instead of `printf("%s", user_input)`), an attacker can supply format tokens like `%x` to read arbitrary memory off the stack, or `%n` to write data to arbitrary memory addresses (such as overwriting the Global Offset Table).

    ./binary $(python -c 'print "\x24\x97\x04\x08" + "%x " * 10 + "%n"')

:five: Return to libc (Ret2libc) :

In scenarios where the stack is non-executable (NX bit set), shellcode injection will fail. Instead, construct a payload that overwrites EIP with the address of the `system()` function from the C standard library (libc), passing it a pointer to the string `"/bin/sh"`.

# Questions and answers

:question: What is the Instruction Pointer (EIP/RIP)?

> The instruction pointer is a CPU register that holds the memory address of the next instruction to be executed by the processor. Overwriting this register allows an attacker to divert execution to arbitrary code.

:question: Why is the `gets()` function dangerous?

> The `gets()` function reads characters from standard input and stores them in a buffer until a newline character or EOF is encountered. It performs no bounds checking, meaning it will continuously write data past the end of the allocated buffer, inevitably corrupting adjacent memory space.

:question: What does a NOP sled (`\x90`) do?

> A NOP (No Operation) sled is a sequence of NOP instructions placed before shellcode. Since stack memory addresses can shift slightly due to environment variables, pointing the EIP register anywhere within the NOP sled will cause the CPU to execute the NOPs sequentially until it safely slides into the actual shellcode payload.

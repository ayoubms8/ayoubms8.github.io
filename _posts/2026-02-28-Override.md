# Introduction :

Reverse engineering involves disassembling and analyzing compiled binary executables to deduce their logic, structure, and potential vulnerabilities without access to the original source code. In advanced exploitation, attackers must circumvent binary protection mechanisms applied by the compiler.

# Project goals :

Override is the culmination of the 1337 system security track. It requires intense reverse engineering of stripped, 32-bit x86 binaries. The goal is to bypass logic checks, dismantle "bomb-lab" style executables, and exploit complex memory corruption vulnerabilities.

# Walkthrough :

:one: Static Analysis of Stripped Binaries :

A stripped binary lacks debugging symbols (function names, variable names). Use tools like Ghidra or IDA Pro to decompile the assembly instructions back into C-like pseudocode. Analyze control flow graphs to understand the logic.

:two: Dynamic Tracing :

Run the binary within a debugger (GDB) or trace system calls (`strace`) and library calls (`ltrace`) to observe how the program interacts with the operating system and memory in real-time.

:three: Dismantling Logic Puzzles :

Some levels require inputting precise data structures or passwords derived from complex mathematical transformations within the binary. Analyze the assembly instructions (`add`, `sub`, `xor`, `shl`) to reverse the mathematical operations and derive the correct input.

:four: Defeating Anti-Debugging :

Executables may implement `ptrace` checks to determine if they are being run under a debugger. If a debugger is detected, the program halts.

    if (ptrace(PTRACE_TRACEME, 0, 1, 0) < 0) {
        exit(1);
    }

Modify the binary execution flow in GDB by altering the instruction pointer or zeroing out the return value in the EAX register after the `ptrace` call to bypass this check.

:five: Advanced Exploitation (Off-by-one, Use-After-Free) :

Exploit subtle memory management flaws. An off-by-one error allows an attacker to overwrite a single byte outside a buffer, often modifying the least significant byte of a saved base pointer, shifting the stack frame execution upon return. Use-After-Free vulnerabilities occur when memory is allocated, freed, and subsequently accessed, allowing attackers to overwrite the heap layout and hijack function pointers.

# Questions and answers

:question: What does it mean when a binary is "stripped"?

> Stripping a binary removes symbolic information, such as function names and variable identifiers, that are typically used for debugging. This reduces the file size but makes static analysis significantly more difficult, as the analyst only sees memory addresses and assembly instructions.

:question: What is the purpose of the EAX register in x86 architecture?

> The EAX (Accumulator) register is primarily used for arithmetic operations and I/O port access. Crucially, in standard C calling conventions (cdecl), the return value of a function is stored in the EAX register before returning to the caller.

:question: What is an off-by-one vulnerability?

> An off-by-one vulnerability is a specific type of buffer overflow where the attacker can write exactly one byte past the boundary of the allocated buffer. This is typically caused by a logic error, such as using `<=` instead of `<` in a loop condition controlling a memory copy operation.

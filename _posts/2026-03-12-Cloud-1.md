# Introduction :

Infrastructure as Code (IaC) is the process of managing and provisioning computing infrastructure through machine-readable definition files, rather than physical hardware configuration or interactive configuration tools. This methodology ensures consistency, repeatability, and version control for server environments.

# Project goals :

Cloud-1 is a 1337 project aimed at mastering cloud deployments. The objective is to utilize a Cloud Provider (AWS, GCP, or Azure) to provision an entire network architecture (VPC, Subnets, Security Groups, Compute Instances) using Terraform, and subsequently configure the software on those instances using Ansible.

# Walkthrough :

:one: Setting up the Provider Configuration (Terraform) :

Define the cloud provider and necessary authentication credentials within the Terraform configuration files. 

    provider "aws" {
      region = "eu-west-3"
      access_key = var.aws_access_key
      secret_key = var.aws_secret_key
    }

:two: Provisioning Network Infrastructure :

Code the infrastructure layout. Create a Virtual Private Cloud (VPC), define public and private subnets, instantiate an Internet Gateway, and configure routing tables to ensure compute instances have the correct inbound and outbound access.

    resource "aws_vpc" "main" {
      cidr_block = "10.0.0.0/16"
    }

:three: Deploying Compute Resources :

Define the EC2 instances (or equivalent VMs) required for the application stack. Specify the Amazon Machine Image (AMI), instance type, and assign Security Groups to restrict traffic to necessary ports (e.g., port 22 for SSH, port 80/443 for HTTP/HTTPS).

:four: Configuration Management (Ansible) :

Once Terraform provisions the hardware layer, Ansible connects to the newly created instances via SSH to configure the software layer. Define playbooks in YAML.

    - name: Configure Web Server
      hosts: webservers
      become: yes
      tasks:
        - name: Install Nginx
          apt:
            name: nginx
            state: present

:five: State Synchronization :

Execute `terraform apply` to instruct Terraform to build the declarative architecture. The state of the infrastructure is recorded in a `terraform.tfstate` file, ensuring future changes are calculated as deltas against the existing environment. Follow this by executing the Ansible playbooks to finalize the server configuration.

# Questions and answers

:question: What is idempotent infrastructure?

> Idempotence in IaC means that applying a configuration multiple times yields the exact same state as applying it once. If the specified state is already achieved, the configuration tool (like Ansible or Terraform) will perform no actions, preventing duplicated resources or configuration errors.

:question: Why separate provisioning (Terraform) from configuration (Ansible)?

> While tools can overlap, Terraform is designed as an orchestrator to manage immutable infrastructure state and resource lifecycles (networking, firewalls, VMs). Ansible is designed as a configuration manager, executing procedural tasks on existing machines (installing packages, modifying configuration files). Separating them leverages the specific strengths of both tools.

:question: What is a Security Group in cloud computing?

> A Security Group acts as a stateful virtual firewall for compute instances, controlling inbound and outbound traffic at the network interface level based on predefined rules regarding IP protocols, port numbers, and source/destination IP addresses.

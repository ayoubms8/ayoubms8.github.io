# Introduction :

When an x86 computer powers on, it starts in 16-bit Real Mode — an execution environment almost identical to the 1978 Intel 8086 CPU. The motherboard firmware (BIOS or UEFI CSM) performs hardware initialization (POST), locates a bootable device, and loads the first 512-byte sector into physical memory at address `0x7C00`. Writing an entire operating system within a 512-byte master boot record (MBR) is notoriously tedious and error-prone.

Enter the **Multiboot Specification**, a standard created by the Free Software Foundation (FSF) and utilized by modern bootloaders like **GRUB** (GRand Unified Bootloader). Multiboot bridges the gap between hardware initialization and kernel execution: the bootloader switches the CPU into 32-bit Protected Mode, sets up flat segmentation, gathers system memory maps, and hands control over to our kernel executable at a predefined entry point.

**KFS-1 (Kernel From Scratch 1)** is the gateway project to operating system architecture at 42. In this project, we cast aside standard C libraries (`libc`), memory allocators, and system calls to build a bare-metal 32-bit kernel from raw assembly and freestanding C, complete with a custom VGA display engine.

---

# Project Goals :

The primary objective of KFS-1 is to create a bootable x86 kernel that complies with the Multiboot standard and directly controls physical hardware without any underlying operating system:

1. **Multiboot Compliance**: Implement a compliant Multiboot header embedded in the binary so GRUB recognizes and boots it.
2. **Linker Script**: Craft an ELF32 linker script organizing memory sections (`.text`, `.rodata`, `.data`, `.bss`) starting at `0x00100000` (1 MiB), avoiding legacy BIOS memory reserved below 1 MiB.
3. **Assembly Bootstrap**: Set up a kernel stack pointer (`ESP`), clear CPU flags, verify the Multiboot magic value, and jump into C code.
4. **VGA Text Mode Driver**: Drive the video memory mapped at `0x000B8000` to render characters, colors, and handle cursor positioning.
5. **Terminal Discipline**: Support line wrapping, screen scrolling upon reaching row 25, and control characters (`\n`, `\r`, `\t`, `\b`).
6. **Kernel Printing (`printk`)**: Implement a formatted printer supporting string, integer, hex, and pointer conversions.

# Boot Sequence Architecture :

The transition from firmware to our kernel code follows a strictly defined hardware pipeline:

```
┌─────────────────┐
│   Power On /    │  Hardware reset vector (0xFFFFFFF0)
│    BIOS POST    │  Initializes buses, memory controllers, and devices
└────────┬────────┘
         │
         ▼
┌─────────────────┐
│  GRUB Bootloader│  Loads kernel binary from ISO/disk
│  (Multiboot)    │  Switches CPU to 32-bit Protected Mode (A20 gate enabled)
└────────┬────────┘  Passes EAX = 0x2BADB002, EBX = multiboot_info ptr
         │
         ▼
┌─────────────────┐
│ boot.s (_start) │  Initializes ESP with static stack buffer
│ Assembly Entry  │  Clears EFLAGS, verifies multiboot magic
└────────┬────────┘
         │
         ▼
┌─────────────────┐
│   kmain.c       │  Initializes VGA text buffer at 0xB8000
│   C Execution   │  Enables hardware cursor, prints banner via printk()
└─────────────────┘
```

# Walkthrough :

## :one: The Multiboot Header

For GRUB to identify our binary as a bootable kernel, the executable must contain a 32-bit aligned **Multiboot Header** within its first 8192 bytes. The header structure requires three mandatory 32-bit fields:

* **Magic Number (`0x1BADB002`)**: Identifies the Multiboot signature.
* **Flags**: Bitmask requesting specific bootloader behaviors (e.g., page-align modules, provide memory map).
* **Checksum**: A value that, when added to `magic + flags`, produces a sum of zero (`-(magic + flags)`).

```nasm
; boot.s - Multiboot Header and Kernel Entry Point
[BITS 32]

MB_ALIGN     equ 1 << 0                   ; Align loaded modules on 4KB page boundaries
MB_MEMINFO   equ 1 << 1                   ; Provide memory map to kernel
MB_FLAGS     equ MB_ALIGN | MB_MEMINFO    ; Multiboot flags
MB_MAGIC     equ 0x1BADB002               ; Multiboot magic constant
MB_CHECKSUM  equ -(MB_MAGIC + MB_FLAGS)   ; Checksum: magic + flags + checksum = 0

section .multiboot
align 4
    dd MB_MAGIC
    dd MB_FLAGS
    dd MB_CHECKSUM
```

## :two: Linker Script & Memory Layout

Operating system kernels should not be loaded at physical address `0x00000000`. The lowest 1 MiB of RAM contains critical Real Mode data structures, including the Interrupt Vector Table (IVT), BIOS Data Area (BDA), and memory-mapped hardware buffers (such as the VGA framebuffer at `0xA0000`–`0xBFFFF`).

We configure our GNU Linker (`ld`) script to place the kernel starting at `1 MiB` (`0x00100000`):

```ld
/* linker.ld - Kernel Linker Script */
ENTRY(_start)
OUTPUT_FORMAT(elf32-i386)
OUTPUT_ARCH(i386)

SECTIONS
{
    /* The kernel will be loaded at 1MB physical memory */
    . = 0x00100000;

    /* First put the multiboot header, as it is required to be put very early
       early in the first 8KB of the image */
    .text BLOCK(4K) : ALIGN(4K)
    {
        *(.multiboot)
        *(.text*)
    }

    /* Read-only data (constants, string literals) */
    .rodata BLOCK(4K) : ALIGN(4K)
    {
        *(.rodata*)
    }

    /* Read-write initialized data */
    .data BLOCK(4K) : ALIGN(4K)
    {
        *(.data*)
    }

    /* Read-write uninitialized data (zero-initialized) and stack */
    .bss BLOCK(4K) : ALIGN(4K)
    {
        *(COMMON)
        *(.bss*)
    }

    kernel_end = .;
}
```

## :three: Assembly Bootstrap (`_start`)

When GRUB transfers control to `_start`, the CPU is in 32-bit Protected Mode, interrupts are disabled, and paging is disabled. However, **no valid C stack pointer exists**. Because C function calls rely on `ESP` to allocate activation records and push return addresses, we must allocate a dedicated stack block in `.bss` and assign it to `ESP` before invoking any C routines:

```nasm
section .bss
align 16
stack_bottom:
    resb 16384                          ; 16 KiB kernel stack
stack_top:

section .text
global _start
extern kmain

_start:
    ; Establish stack pointer
    mov esp, stack_top

    ; Reset EFLAGS register (clear Direction Flag, Interrupt Flag, etc.)
    push 0
    popf

    ; GRUB puts magic (0x2BADB002) in EAX, and multiboot_info address in EBX
    ; Push them as arguments to kmain(uint32_t magic, multiboot_info_t *mbi)
    push ebx
    push eax

    ; Call the C kernel entry point
    call kmain

    ; If kmain returns, disable interrupts and enter infinite halt loop
.halt:
    cli
    hlt
    jmp .halt
```

## :four: VGA Text Mode Display Driver

Standard PC-compatible video controllers provide an 80-column by 25-row text mode accessible via memory-mapped I/O starting at physical address `0x000B8000`.

### Cell Structure
Each screen cell consists of **2 consecutive bytes** in video RAM:

```
 15              12 11              8 7                             0
┌──────────────────┬─────────────────┬───────────────────────────────┐
│ Background Color │ Foreground Color│         ASCII Character       │
│     (4 bits)     │    (4 bits)     │            (8 bits)           │
└──────────────────┴─────────────────┴───────────────────────────────┘
```

The 16 standard VGA colors are:

| Code | Color | Code | Color |
|---|---|---|---|
| `0x0` | Black | `0x8` | Dark Grey |
| `0x1` | Blue | `0x9` | Light Blue |
| `0x2` | Green | `0xA` | Light Green |
| `0x3` | Cyan | `0xB` | Light Cyan |
| `0x4` | Red | `0xC` | Light Red |
| `0x5` | Magenta | `0xD` | Pink |
| `0x6` | Brown | `0xE` | Light Brown / Yellow |
| `0x7` | Light Grey | `0xF` | White |

### Video Driver Implementation

```c
/* vga.h - VGA Text Mode Driver */
#ifndef VGA_H
#define VGA_H

#include <stdint.h>
#include <stddef.h>

#define VGA_WIDTH   80
#define VGA_HEIGHT  25
#define VGA_MEMORY  ((volatile uint16_t *)0x000B8000)

enum vga_color {
    VGA_COLOR_BLACK         = 0,
    VGA_COLOR_BLUE          = 1,
    VGA_COLOR_GREEN         = 2,
    VGA_COLOR_CYAN          = 3,
    VGA_COLOR_RED           = 4,
    VGA_COLOR_MAGENTA       = 5,
    VGA_COLOR_BROWN         = 6,
    VGA_COLOR_LIGHT_GREY    = 7,
    VGA_COLOR_DARK_GREY     = 8,
    VGA_COLOR_LIGHT_BLUE    = 9,
    VGA_COLOR_LIGHT_GREEN   = 10,
    VGA_COLOR_LIGHT_CYAN    = 11,
    VGA_COLOR_LIGHT_RED     = 12,
    VGA_COLOR_LIGHT_MAGENTA = 13,
    VGA_COLOR_LIGHT_BROWN   = 14,
    VGA_COLOR_WHITE         = 15,
};

static inline uint8_t vga_entry_color(enum vga_color fg, enum vga_color bg) {
    return fg | (bg << 4);
}

static inline uint16_t vga_entry(unsigned char uc, uint8_t color) {
    return (uint16_t)uc | ((uint16_t)color << 8);
}

void vga_init(void);
void vga_putc(char c);
void vga_puts(const char *str);
void vga_clear(void);
void vga_set_color(enum vga_color fg, enum vga_color bg);
void vga_set_cursor(size_t x, size_t y);

#endif
```

## :five: Port I/O and Hardware Cursor

On x86, peripheral hardware communication occurs through a dedicated I/O address space using the assembly instructions `in` and `out`. We write inline assembly primitives:

```c
/* io.h - x86 Port I/O Wrappers */
static inline void outb(uint16_t port, uint8_t val) {
    __asm__ volatile ("outb %0, %1" : : "a"(val), "Nd"(port));
}

static inline uint8_t inb(uint16_t port) {
    uint8_t ret;
    __asm__ volatile ("inb %1, %0" : "=a"(ret) : "Nd"(port));
    return ret;
}
```

The VGA CRT Controller communicates through I/O ports `0x3D4` (index register) and `0x3D5` (data register). The blinking hardware cursor position is an offset from `0` to `80 * 25 - 1`:

```c
void vga_set_cursor(size_t x, size_t y) {
    uint16_t pos = y * VGA_WIDTH + x;

    // Send cursor high byte to register 0x0E
    outb(0x3D4, 0x0E);
    outb(0x3D5, (uint8_t)((pos >> 8) & 0xFF));

    // Send cursor low byte to register 0x0F
    outb(0x3D4, 0x0F);
    outb(0x3D5, (uint8_t)(pos & 0xFF));
}
```

## :six: Terminal Scrolling and Control Characters

A usable console must handle line boundaries, newlines (`\n`), carriage returns (`\r`), backspaces (`\b`), tabs (`\t`), and scroll rows upwards when the cursor reaches the bottom:

```c
static size_t term_row;
static size_t term_col;
static uint8_t term_color;

static void vga_scroll(void) {
    // Copy rows 1..24 to rows 0..23
    for (size_t y = 1; y < VGA_HEIGHT; y++) {
        for (size_t x = 0; x < VGA_WIDTH; x++) {
            VGA_MEMORY[(y - 1) * VGA_WIDTH + x] = VGA_MEMORY[y * VGA_WIDTH + x];
        }
    }
    // Clear the bottom row
    uint16_t blank = vga_entry(' ', term_color);
    for (size_t x = 0; x < VGA_WIDTH; x++) {
        VGA_MEMORY[(VGA_HEIGHT - 1) * VGA_WIDTH + x] = blank;
    }
    term_row = VGA_HEIGHT - 1;
}

void vga_putc(char c) {
    if (c == '\n') {
        term_col = 0;
        term_row++;
    } else if (c == '\r') {
        term_col = 0;
    } else if (c == '\b') {
        if (term_col > 0) {
            term_col--;
            VGA_MEMORY[term_row * VGA_WIDTH + term_col] = vga_entry(' ', term_color);
        }
    } else if (c == '\t') {
        term_col = (term_col + 4) & ~3;
    } else {
        VGA_MEMORY[term_row * VGA_WIDTH + term_col] = vga_entry(c, term_color);
        term_col++;
    }

    if (term_col >= VGA_WIDTH) {
        term_col = 0;
        term_row++;
    }
    if (term_row >= VGA_HEIGHT) {
        vga_scroll();
    }
    vga_set_cursor(term_col, term_row);
}
```

## :seven: Custom `printk` Implementation

Without `printf` from `libc`, we build a freestanding variadic formatter using compiler built-in `va_list`, `va_start`, and `va_arg`:

```c
#include <stdarg.h>

void printk(const char *fmt, ...) {
    va_list args;
    va_start(args, fmt);

    for (const char *p = fmt; *p != '\0'; p++) {
        if (*p != '%') {
            vga_putc(*p);
            continue;
        }
        p++;
        switch (*p) {
            case 'c':
                vga_putc((char)va_arg(args, int));
                break;
            case 's': {
                const char *s = va_arg(args, const char *);
                vga_puts(s ? s : "(null)");
                break;
            }
            case 'd':
            case 'i':
                print_dec(va_arg(args, int32_t));
                break;
            case 'x':
                print_hex(va_arg(args, uint32_t));
                break;
            case 'p':
                vga_puts("0x");
                print_hex((uint32_t)va_arg(args, void *));
                break;
            case '%':
                vga_putc('%');
                break;
            default:
                vga_putc('%');
                vga_putc(*p);
                break;
        }
    }
    va_end(args);
}
```

## :eight: Building and Running in QEMU

We package the compiled ELF kernel into an ISO image using `grub-mkrescue` and a simple `grub.cfg`:

```bash
# Directory tree
# isodir/
# └── boot/
#     ├── grub/
#     │   └── grub.cfg
#     └── kfs.bin

# grub.cfg
menuentry "42 KFS-1 Kernel" {
    multiboot /boot/kfs.bin
    boot
}
```

```bash
# Build with GCC freestanding flags
$ gcc -m32 -ffreestanding -fno-builtin -fno-stack-protector -nostdlib -Wall -Wextra -c kmain.c -o kmain.o
$ nasm -f elf32 boot.s -o boot.o
$ ld -m elf_i386 -T linker.ld -o kfs.bin boot.o kmain.o

# Generate bootable ISO and test with QEMU
$ mkdir -p isodir/boot/grub
$ cp kfs.bin isodir/boot/
$ cp grub.cfg isodir/boot/grub/
$ grub-mkrescue -o kfs.iso isodir
$ qemu-system-i386 -cdrom kfs.iso
```

# Key Takeaways & What's Next :

KFS-1 establishes the foundation of operating system programming. We successfully transitioned from the GRUB bootloader into 32-bit execution mode, built our own hardware driver from physical memory addresses and I/O ports, and established diagnostic output without depending on a single line of external software.

However, our CPU is currently running on the temporary, rudimentary segments configured by GRUB. In **KFS-2**, we will take full control of CPU memory segmentation by constructing our own **Global Descriptor Table (GDT)** and building a **Kernel Stack Frame Unwinder** to inspect running execution states and handle crashes.

# Introduction :

In 32-bit x86 Protected Mode, the processor enforces memory access privileges through two complementary hardware mechanisms: **Segmentation** and **Paging**. Before modern operating systems can enable virtual memory and page tables, the CPU fundamentally demands that segmentation is initialized.

While GRUB boots the kernel into protected mode with default segment selectors, an operating system cannot rely on bootloader defaults. The bootloader's segments are temporary, offer no distinction between kernel and user privilege rings, and may reside in memory regions scheduled for overwrite.

In **KFS-2 (Kernel From Scratch 2)**, we take full command of processor memory architecture by constructing our own **Global Descriptor Table (GDT)**, placing it at physical address `0x00000800`, and writing a **Kernel Stack Inspector and Debugging Shell** capable of walking call frames and inspecting memory in real time.

---

# Project Goals :

1. **Construct a Complete GDT**: Define segments for Kernel Space (Ring 0) and User Space (Ring 3), covering code, data, and stack segments.
2. **Fixed Address Installation**: Store the GDT table at the exact physical memory location `0x00000800` as prescribed by the 42 subject specification.
3. **Flushing & Reloading Segment Registers**: Load the GDTR register using `lgdt`, reload `CS` via an assembly far jump, and reload data segment registers (`DS`, `ES`, `FS`, `GS`, `SS`).
4. **Kernel Stack Frame Analysis**: Understand the x86 stack frame layout dictated by `EBP` and `ESP`.
5. **Stack Unwinder & Memory Dumper**: Implement a backtrace function that traverses the frame pointer chain and prints caller return addresses.
6. **Diagnostic Shell**: Provide a minimal interactive prompt supporting commands like `stack`, `dump`, `reboot`, and `halt`.

# Segmentation & The GDT :

In IA-32, memory addresses referenced by instructions are **Logical Addresses** (composed of a Segment Selector and an Offset). The segmentation hardware translates the logical address into a **Linear Address** by adding the segment base address.

```
Logical Address: [ Segment Selector (16-bit) : Offset (32-bit) ]
                         │
                         ▼
             ┌─────────────────────────┐
             │ Global Descriptor Table │
             ├─────────────────────────┤
             │ Descriptor [Index]      │ ──► Base Address (32-bit) + Limit
             └─────────────────────────┘
                         │
                         ▼
Linear Address:  [ Base Address + Offset ]
```

Each GDT entry is an **8-byte (64-bit)** descriptor encoding the segment's base, limit, privilege ring, and access flags:

```
 63          56 55 54 53 52 51    48 47          40 39        16 15            0
┌──────────────┬──┬──┬──┬──┬────────┬──────────────┬────────────┬──────────────┐
│  Base 31..24 │G │DB│0 │A │Lim19..16│  Access Byte │ Base 23..0 │  Limit 15..0 │
└──────────────┴──┴──┴──┴──┴────────┴──────────────┴────────────┴──────────────┘
```

### Access Byte Anatomy (Bits 40–47)
* **P (Present)**: Bit 7. Must be `1` for valid segments.
* **DPL (Descriptor Privilege Level)**: Bits 5–6. Ring 0 (`00b`) for kernel, Ring 3 (`11b`) for user space.
* **S (Descriptor Type)**: Bit 4. `1` for code/data segments, `0` for system segments (TSS, LDT).
* **E (Executable)**: Bit 3. `1` for code segments, `0` for data/stack segments.
* **DC (Direction / Conforming)**: Bit 2. For data: `0` grows up, `1` grows down. For code: `0` non-conforming.
* **RW (Readable / Writable)**: Bit 1. For code: readable (`1`). For data: writable (`1`).
* **A (Accessed)**: Bit 0. Initialized to `0`, CPU sets it to `1` when accessed.

### Granularity & Flags (Bits 52–55)
* **G (Granularity)**: Bit 55. If `1`, limit is multiplied by 4 KiB pages (allows 4 GiB span).
* **DB (Size Flag)**: Bit 54. `1` for 32-bit protected mode operations, `0` for 16-bit.

# Walkthrough :

## :one: Defining GDT Structures in C

```c
/* gdt.h - Global Descriptor Table Header */
#ifndef GDT_H
#define GDT_H

#include <stdint.h>

#define GDT_TARGET_ADDR 0x00000800
#define GDT_ENTRY_COUNT 7

struct gdt_entry {
    uint16_t limit_low;     // Lower 16 bits of limit
    uint16_t base_low;      // Lower 16 bits of base
    uint8_t  base_middle;   // Next 8 bits of base
    uint8_t  access;        // Access flags
    uint8_t  granularity;   // Granularity and upper 4 bits of limit
    uint8_t  base_high;     // Final 8 bits of base
} __attribute__((packed));

struct gdt_ptr {
    uint16_t limit;         // Size of GDT table - 1
    uint32_t base;          // Address of the first GDT entry
} __attribute__((packed));

void gdt_init(void);

#endif
```

## :two: Installing the GDT at `0x00000800`

The 42 project requirements specify that the GDT must be written directly to physical address `0x00000800`. We cast this memory pointer directly:

```c
/* gdt.c - Global Descriptor Table Implementation */
#include "gdt.h"
#include <string.h>

extern void gdt_flush(uint32_t gdt_ptr_addr);

static void gdt_set_gate(int32_t num, uint32_t base, uint32_t limit, uint8_t access, uint8_t gran) {
    struct gdt_entry *gdt = (struct gdt_entry *)GDT_TARGET_ADDR;

    gdt[num].base_low    = (base & 0xFFFF);
    gdt[num].base_middle = (base >> 16) & 0xFF;
    gdt[num].base_high   = (base >> 24) & 0xFF;

    gdt[num].limit_low   = (limit & 0xFFFF);
    gdt[num].granularity = ((limit >> 16) & 0x0F) | (gran & 0xF0);
    gdt[num].access      = access;
}

void gdt_init(void) {
    struct gdt_ptr gp;

    gp.limit = (sizeof(struct gdt_entry) * GDT_ENTRY_COUNT) - 1;
    gp.base  = GDT_TARGET_ADDR;

    // 0x00: Null descriptor
    gdt_set_gate(0, 0, 0, 0, 0);

    // 0x08: Kernel Code Segment (Ring 0, RX)
    gdt_set_gate(1, 0, 0xFFFFFFFF, 0x9A, 0xCF);

    // 0x10: Kernel Data Segment (Ring 0, RW)
    gdt_set_gate(2, 0, 0xFFFFFFFF, 0x92, 0xCF);

    // 0x18: Kernel Stack Segment (Ring 0, RW)
    gdt_set_gate(3, 0, 0xFFFFFFFF, 0x92, 0xCF);

    // 0x20: User Code Segment (Ring 3, RX)
    gdt_set_gate(4, 0, 0xFFFFFFFF, 0xFA, 0xCF);

    // 0x28: User Data Segment (Ring 3, RW)
    gdt_set_gate(5, 0, 0xFFFFFFFF, 0xF2, 0xCF);

    // 0x30: User Stack Segment (Ring 3, RW)
    gdt_set_gate(6, 0, 0xFFFFFFFF, 0xF2, 0xCF);

    // Flush and reload CPU segment registers
    gdt_flush((uint32_t)&gp);
}
```

## :three: Flushing Segments in Assembly

Loading the GDT with the `lgdt` instruction tells the processor where the table is, but does **not** update the hidden segment descriptor caches inside the CPU:

* `CS` (Code Segment) cannot be reloaded with `mov`. It must be refreshed with a **far jump** (`jmp 0x08:.reload_cs`).
* `DS`, `ES`, `SS`, `FS`, and `GS` are updated by moving the selector offset `0x10` into each register.

```nasm
; gdt_flush.s - Assembly routine to reload segment selectors
[BITS 32]
global gdt_flush

gdt_flush:
    mov eax, [esp + 4]      ; Get pointer to gdt_ptr passed as argument
    lgdt [eax]              ; Load GDT pointer into CPU GDTR register

    ; Far jump to flush CS pipeline and set CS to 0x08 (Kernel Code)
    jmp 0x08:.reload_cs

.reload_cs:
    ; Reload data segment selectors with 0x10 (Kernel Data)
    mov ax, 0x10
    mov ds, ax
    mov es, ax
    mov fs, ax
    mov gs, ax
    mov ss, ax              ; Set stack segment selector

    ret
```

## :four: The x86 Call Stack & Frame Pointer

When a standard C function is called on 32-bit x86, the compiler constructs a stack frame using the base pointer (`EBP`):

```
Higher Memory
┌───────────────────────────┐
│ Argument 2                │ [EBP + 12]
├───────────────────────────┤
│ Argument 1                │ [EBP + 8]
├───────────────────────────┤
│ Return Address (EIP)      │ [EBP + 4]  <-- Pushed automatically by CALL
├───────────────────────────┤
│ Saved Old EBP             │ [EBP]      <-- Pushed by prologue (push ebp)
├───────────────────────────┤
│ Local Variables           │ [EBP - 4]
│                           │ [EBP - 8]
└───────────────────────────┘
Lower Memory (ESP points to top of stack)
```

The prologue of every standard function is:
```nasm
push ebp
mov ebp, esp
sub esp, N
```

Because `EBP` points directly to the saved caller's `EBP`, stack frames form a **linked list** going all the way back to `_start`. The word immediately above `[EBP]` (`[EBP + 4]`) is the return address of the caller!

## :five: Stack Unwinder Implementation

To print an execution backtrace, we read the current `EBP` and traverse the chain:

```c
/* stack.c - Kernel Stack Unwinder */
#include "printk.h"
#include <stdint.h>

struct stack_frame {
    struct stack_frame *next;
    uint32_t return_address;
};

void kernel_backtrace(uint32_t max_frames) {
    struct stack_frame *frame;

    // Read current EBP using inline assembly
    __asm__ volatile ("mov %%ebp, %0" : "=r"(frame));

    printk("\n=== [ KERNEL STACK BACKTRACE ] ===\n");
    printk("Frame        Base Pointer (EBP)   Return Addr (EIP)\n");
    printk("---------------------------------------------------\n");

    uint32_t depth = 0;
    while (frame != 0 && depth < max_frames) {
        // Sanity checks: EBP must be 4-byte aligned and in a plausible stack range
        if (((uint32_t)frame & 0x3) != 0 || (uint32_t)frame < 0x00100000) {
            break;
        }

        printk("#%-2d          0x%x           0x%x\n", depth, (uint32_t)frame, frame->return_address);

        frame = frame->next;
        depth++;
    }
    printk("===================================================\n\n");
}
```

## :six: Stack and Memory Hex Dumper

A kernel inspector needs to dump raw memory in combined hexadecimal and ASCII format:

```c
void dump_memory(const void *addr, size_t size) {
    const uint8_t *ptr = (const uint8_t *)addr;
    char ascii[17];
    ascii[16] = '\0';

    printk("Dumping %d bytes at %p:\n", size, addr);

    for (size_t i = 0; i < size; i++) {
        if (i % 16 == 0) {
            printk("%p: ", &ptr[i]);
        }

        printk("%02x ", ptr[i]);
        ascii[i % 16] = (ptr[i] >= 32 && ptr[i] <= 126) ? (char)ptr[i] : '.';

        if ((i + 1) % 16 == 0 || i + 1 == size) {
            // Pad remaining spacing if line is short
            if (i + 1 == size && (i + 1) % 16 != 0) {
                for (size_t pad = 0; pad < 16 - ((i + 1) % 16); pad++) {
                    printk("   ");
                }
            }
            printk(" |%s|\n", ascii);
            memset(ascii, 0, sizeof(ascii));
        }
    }
}
```

## :seven: Interactive Diagnostic Shell

We wire a simple command loop that allows inspecting memory and resetting the CPU:

```c
void cmd_reboot(void) {
    printk("Rebooting system via 8042 Keyboard Controller...\n");
    // Pulse CPU reset line by writing 0xFE to port 0x64
    uint8_t temp;
    do {
        temp = inb(0x64);
        if (temp & 1)
            (void)inb(0x60);
    } while (temp & 2);

    outb(0x64, 0xFE);

    // Fallback: Triple fault by loading invalid IDT and triggering interrupt
    struct { uint16_t limit; uint32_t base; } __attribute__((packed)) null_idtr = { 0, 0 };
    __asm__ volatile ("lidt %0; int3" : : "m"(null_idtr));
}

void cmd_halt(void) {
    printk("Halting CPU...\n");
    __asm__ volatile ("cli; hlt");
}
```

# Key Takeaways & What's Next :

In KFS-2, we gained complete control over hardware segmentation. We proved that:
1. The GDT successfully lives at physical address `0x00000800`.
2. Segments are split into distinct Ring 0 (supervisor) and Ring 3 (user) regions.
3. The stack frame architecture (`EBP`/`ESP`) enables runtime inspection and post-mortem stack dumping.

While segmentation divides memory into logical blocks, it lacks page-level protection, on-demand paging, and memory isolation between independent processes. In **KFS-3**, we will tackle **Two-Tier Paging and Virtual Memory Management**.

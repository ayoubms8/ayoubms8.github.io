# Introduction :

In the previous KFS milestones, our kernel operated entirely in a synchronous, polling loop. When our diagnostic shell wanted to know if a key was pressed, it had to constantly poll hardware I/O ports in a tight CPU cycle — wasting processor cycles and rendering true multitasking impossible.

To build a responsive operating system, hardware devices must be able to signal the CPU asynchronously whenever an event occurs. Simultaneously, the CPU must be able to intercept synchronous internal exceptions — like a division by zero or a page fault — and divert execution to an operating system handler instead of crashing the physical machine.

In **KFS-4 (Kernel From Scratch 4)**, we establish the event-driven backbone of our operating system:
* Constructing the **Interrupt Descriptor Table (IDT)** with all 256 gates.
* Handling Intel CPU exceptions (vectors 0–31) with uniform stack frame stubs.
* Remapping the **Dual 8259 Programmable Interrupt Controller (PIC)** to resolve the historical PC-AT vector collision.
* Configuring the **Programmable Interval Timer (PIT)** on IRQ0 for system clock ticks.
* Building a fully interrupt-driven **PS/2 Keyboard Driver** on IRQ1 with scancode translation and a circular input buffer.
* Integrating an interactive kernel shell driven entirely by hardware interrupts.

# Architecture of x86 Interrupts :

Interrupts on x86 belong to two distinct categories:

1. **Synchronous Exceptions (Internal)**: Generated by the CPU itself during instruction execution (e.g., `#DE` Divide-by-zero, `#GP` General Protection Fault, `#PF` Page Fault).
2. **Asynchronous Interrupts (External / Hardware)**: Generated by external peripherals (keyboards, timers, disk controllers, NICs) sent to the CPU via the Interrupt Controller lines (`INTR` pin).

```
Hardware Device (Keyboard / Timer)
                │
                ▼
┌───────────────────────────────┐
│  Dual 8259 PIC (Master/Slave) │
└───────────────┬───────────────┘
                │  IRQ line triggered -> translates to vector (e.g., 33)
                ▼
┌───────────────────────────────┐
│     CPU Execution Stream      │
│  - Suspends current code      │
│  - Pushes EFLAGS, CS, EIP     │
│  - Reads IDT[33]              │
└───────────────┬───────────────┘
                │
                ▼
┌───────────────────────────────┐
│   ISR Stub (Assembly)         │  Saves GPRs (pusha), sets Kernel DS
└───────────────┬───────────────┘
                │
                ▼
┌───────────────────────────────┐
│   C Interrupt Dispatcher      │  Calls keyboard_handler(), sends PIC EOI
└───────────────┬───────────────┘
                │
                ▼
┌───────────────────────────────┐
│   IRET Instruction            │  Restores registers, returns to user/kernel
└───────────────────────────────┘
```

# The IDT Gate Descriptor :

The **Interrupt Descriptor Table (IDT)** contains 256 entries. Each entry is an 8-byte structure defining where execution should jump when an interrupt vector fires:

```
 63                                48 47  46 45 44 43 40 39       32 31               16 15                0
┌────────────────────────────────────┬───┬─────┬──┬─────┬───────────┬───────────────────┬───────────────────┐
│       Offset High (Bits 16..31)    │ P │ DPL │0 │Type │  Reserved │  Segment Selector │ Offset Low (0..15)│
└────────────────────────────────────┴───┴─────┴──┴─────┴───────────┴───────────────────┴───────────────────┘
```

* **Offset (Bits 0..15 and 48..63)**: 32-bit linear address of the Interrupt Service Routine (ISR).
* **Segment Selector (Bits 16..31)**: Code segment selector in the GDT (`0x08` for Kernel Code).
* **Type (Bits 40..43)**: `0xE` (1110b) specifies a 32-bit Interrupt Gate (which automatically clears the `IF` flag to prevent nested interrupts).
* **DPL (Bits 45..46)**: Privilege ring required to invoke via software `int` instruction (`0` for kernel exceptions, `3` for system calls).
* **P (Present, Bit 47)**: Must be `1` for active gates.

## 2️⃣ Exception Stack Frames & Assembly ISR Stubs

When an exception occurs, the CPU pushes `EFLAGS`, `CS`, and `EIP` onto the stack. For certain exceptions (such as `#GP` 13 and `#PF` 14), the CPU **also pushes an Error Code**. For others (like `#DE` 0 or `#BP` 3), **no error code is pushed**.

To pass a uniform register structure to our C dispatcher, we push a dummy error code `0` for exceptions that do not provide one:

```nasm
; isr.s - Interrupt Service Routine Stubs
[BITS 32]

%macro ISR_NOERRCODE 1
global isr%1
isr%1:
    push 0                  ; Push dummy error code
    push %1                 ; Push interrupt vector number
    jmp isr_common_stub
%endmacro

%macro ISR_ERRCODE 1
global isr%1
isr%1:
    push %1                 ; Interrupt vector number (CPU already pushed error code)
    jmp isr_common_stub
%endmacro

; Define CPU Exceptions 0..31
ISR_NOERRCODE 0   ; 0: Divide by Zero
ISR_NOERRCODE 1   ; 1: Debug
ISR_NOERRCODE 2   ; 2: Non-Maskable Interrupt
ISR_NOERRCODE 3   ; 3: Breakpoint
ISR_NOERRCODE 4   ; 4: Overflow
ISR_NOERRCODE 5   ; 5: Bound Range Exceeded
ISR_NOERRCODE 6   ; 6: Invalid Opcode
ISR_NOERRCODE 7   ; 7: Device Not Available
ISR_ERRCODE   8   ; 8: Double Fault
ISR_NOERRCODE 9   ; 9: Coprocessor Segment Overrun
ISR_ERRCODE   10  ; 10: Invalid TSS
ISR_ERRCODE   11  ; 11: Segment Not Present
ISR_ERRCODE   12  ; 12: Stack-Segment Fault
ISR_ERRCODE   13  ; 13: General Protection Fault
ISR_ERRCODE   14  ; 14: Page Fault
ISR_NOERRCODE 15  ; 15: Reserved
ISR_NOERRCODE 16  ; 16: x87 FPU Error
ISR_ERRCODE   17  ; 17: Alignment Check
ISR_NOERRCODE 18  ; 18: Machine Check
ISR_NOERRCODE 19  ; 19: SIMD Floating-Point Exception
; ... up to 31

extern isr_handler

isr_common_stub:
    pusha                   ; Pushes EDI, ESI, EBP, ESP, EBX, EDX, ECX, EAX

    mov ax, ds
    push eax                ; Save original data segment descriptor

    mov ax, 0x10            ; Load kernel data segment
    mov ds, ax
    mov es, ax
    mov fs, ax
    mov gs, ax

    push esp                ; Pass pointer to stack frame (registers_t *)
    call isr_handler
    add esp, 4              ; Clean up passed parameter

    pop eax                 ; Restore original data segment
    mov ds, ax
    mov es, ax
    mov fs, ax
    mov gs, ax

    popa                    ; Restore General Purpose Registers
    add esp, 8              ; Remove error code and interrupt number from stack
    iret                    ; Pops CS, EIP, EFLAGS, and SS/ESP if privilege change
```

## 3️⃣ Remapping the Dual 8259 PIC

The IBM PC architecture routes hardware interrupts through two cascaded 8259 PIC chips:
* **Master PIC**: Connected to CPU `INTR` line, handles IRQ 0..7 (Ports `0x20` / `0x21`).
* **Slave PIC**: Cascaded onto Master's IRQ2, handles IRQ 8..15 (Ports `0xA0` / `0xA1`).

### The Conflict
By default, the IBM BIOS configures the Master PIC to fire interrupt vectors **`0x08`–`0x0F`**. In Intel 32-bit Protected Mode, however, vectors `0x08`–`0x0F` are reserved for CPU exceptions (e.g., Vector `0x08` is Double Fault `#DF`)! If the timer fires on IRQ0, the CPU thinks a Double Fault occurred and panics.

We solve this by sending **Initialization Command Words (ICW1–ICW4)** to remap the PICs:
* Master PIC remapped to vectors `32..39` (`0x20`–`0x27`).
* Slave PIC remapped to vectors `40..47` (`0x28`–`0x2F`).

```c
/* pic.c - 8259 PIC Remapping */
#include "io.h"

#define PIC1_COMMAND  0x20
#define PIC1_DATA     0x21
#define PIC2_COMMAND  0xA0
#define PIC2_DATA     0xA1

#define ICW1_INIT     0x10
#define ICW1_ICW4     0x01
#define ICW4_8086     0x01
#define PIC_EOI       0x20

void pic_remap(int offset1, int offset2) {
    uint8_t a1 = inb(PIC1_DATA); // Save existing interrupt masks
    uint8_t a2 = inb(PIC2_DATA);

    // ICW1: Start initialization sequence in cascade mode
    outb(PIC1_COMMAND, ICW1_INIT | ICW1_ICW4);
    io_wait();
    outb(PIC2_COMMAND, ICW1_INIT | ICW1_ICW4);
    io_wait();

    // ICW2: Vector offsets
    outb(PIC1_DATA, offset1); // Master offset: 32 (0x20)
    io_wait();
    outb(PIC2_DATA, offset2); // Slave offset: 40 (0x28)
    io_wait();

    // ICW3: Tell Master that Slave is at IRQ2 (0000 0100b = 4)
    outb(PIC1_DATA, 0x04);
    io_wait();
    // Tell Slave its cascade identity is 2
    outb(PIC2_DATA, 0x02);
    io_wait();

    // ICW4: Use 8086/88 mode
    outb(PIC1_DATA, ICW4_8086);
    io_wait();
    outb(PIC2_DATA, ICW4_8086);
    io_wait();

    // Restore saved masks
    outb(PIC1_DATA, a1);
    outb(PIC2_DATA, a2);
}

void pic_send_eoi(uint8_t irq) {
    if (irq >= 8) {
        outb(PIC2_COMMAND, PIC_EOI); // Send EOI to Slave
    }
    outb(PIC1_COMMAND, PIC_EOI);     // Send EOI to Master
}
```

## 4️⃣ Programmable Interval Timer (PIT) Driver

The 8254 PIT oscillates at `1.193182 MHz`. By programming its channel 0 divisor (port `0x40`), we generate regular periodic clock interrupts on IRQ0:

```c
/* pit.c - Timer Driver */
#define PIT_FREQUENCY_HZ 100
#define PIT_BASE_CLOCK   1193182

static volatile uint32_t timer_ticks = 0;

void pit_init(uint32_t frequency) {
    uint32_t divisor = PIT_BASE_CLOCK / frequency;

    // Command byte: Channel 0, access mode lobyte/hibyte, square wave mode
    outb(0x43, 0x36);
    outb(0x40, (uint8_t)(divisor & 0xFF));
    outb(0x40, (uint8_t)((divisor >> 8) & 0xFF));

    register_interrupt_handler(32, pit_handler);
}

void pit_handler(registers_t *regs) {
    timer_ticks++;
    pic_send_eoi(0);
}
```

## 5️⃣ PS/2 Keyboard Driver (IRQ1)

When a key is pressed or released on a standard PS/2 keyboard, the keyboard controller raises **IRQ1** (vector 33) and places a byte (**scancode**) into I/O port `0x60`.

In **Scancode Set 1**:
* **Make Code (Key Press)**: Values between `0x01` and `0x58`.
* **Break Code (Key Release)**: Make code with bit 7 set (`scancode | 0x80`). For instance, Left Shift press is `0x2A`, release is `0xAA`.

```c
/* keyboard.c - PS/2 Keyboard Driver */
#include "keyboard.h"
#include "pic.h"
#include "io.h"

static int shift_active = 0;
static int caps_lock = 0;
static int ctrl_active = 0;

static const char kbd_us[128] = {
    0,  27, '1', '2', '3', '4', '5', '6', '7', '8', '9', '0', '-', '=', '\b',
  '\t', 'q', 'w', 'e', 'r', 't', 'y', 'u', 'i', 'o', 'p', '[', ']', '\n',
    0,  'a', 's', 'd', 'f', 'g', 'h', 'j', 'k', 'l', ';', '\'', '`',
    0, '\\', 'z', 'x', 'c', 'v', 'b', 'n', 'm', ',', '.', '/',   0,
  '*',   0, ' '
};

static const char kbd_us_shift[128] = {
    0,  27, '!', '@', '#', '$', '%', '^', '&', '*', '(', ')', '_', '+', '\b',
  '\t', 'Q', 'W', 'E', 'R', 'T', 'Y', 'U', 'I', 'O', 'P', '{', '}', '\n',
    0,  'A', 'S', 'D', 'F', 'G', 'H', 'J', 'K', 'L', ':', '\"', '~',
    0, '|', 'Z', 'X', 'C', 'V', 'B', 'N', 'M', '<', '>', '?',   0,
  '*',   0, ' '
};

void keyboard_handler(registers_t *regs) {
    uint8_t scancode = inb(0x60);

    // Check if break code (key released)
    if (scancode & 0x80) {
        uint8_t released = scancode & ~0x80;
        if (released == 0x2A || released == 0x36) { // Left/Right Shift
            shift_active = 0;
        } else if (released == 0x1D) {              // Ctrl
            ctrl_active = 0;
        }
    } else {
        // Key pressed (make code)
        if (scancode == 0x2A || scancode == 0x36) {
            shift_active = 1;
        } else if (scancode == 0x3A) {              // Caps Lock toggle
            caps_lock = !caps_lock;
        } else if (scancode == 0x1D) {
            ctrl_active = 1;
        } else {
            char c = (shift_active ^ caps_lock) ? kbd_us_shift[scancode] : kbd_us[scancode];
            if (c) {
                keyboard_enqueue_char(c);
            }
        }
    }

    pic_send_eoi(1);
}
```

## 6️⃣ Circular Input Buffer & Shell Integration

To decouple interrupt latency from terminal processing, incoming keystrokes are pushed into a circular ring buffer:

```c
#define KBD_BUFFER_SIZE 256
static char kbd_ring_buffer[KBD_BUFFER_SIZE];
static volatile uint32_t kbd_head = 0;
static volatile uint32_t kbd_tail = 0;

void keyboard_enqueue_char(char c) {
    uint32_t next = (kbd_head + 1) % KBD_BUFFER_SIZE;
    if (next != kbd_tail) { // Not full
        kbd_ring_buffer[kbd_head] = c;
        kbd_head = next;
    }
}

char kbd_getchar(void) {
    while (kbd_head == kbd_tail) {
        // Halt processor until next hardware interrupt fires
        __asm__ volatile ("hlt");
    }
    char c = kbd_ring_buffer[kbd_tail];
    kbd_tail = (kbd_tail + 1) % KBD_BUFFER_SIZE;
    return c;
}
```

We now have a responsive interactive shell where typing echoes in real time. We add commands to test CPU exceptions safely:

* `divzero`: Performs inline `div %0` with `0` divisor to prove `#DE` vector 0 catches and displays registers.
* `pagefault`: Dereferences address `0xDEADBEEF` to trigger `#PF` vector 14 and verify `CR2` logging.
* `ticks`: Displays timer ticks from PIT IRQ0.

```c
void cmd_test_divzero(void) {
    printk("Triggering intentional Division by Zero (#DE)...\n");
    volatile int a = 42;
    volatile int b = 0;
    volatile int c = a / b;
    (void)c;
}
```

# Key Takeaways :

With KFS-4 complete, our kernel has crossed the threshold from a static proof-of-concept into a fully interactive, interrupt-driven operating system:
1. **IDT & ISR Handling**: All 32 Intel CPU exceptions are cleanly trapped with register state snapshots and stack traces.
2. **PIC Management**: Hardware interrupts from external controllers are cleanly remapped without colliding with protected mode architecture.
3. **Timer & Keyboard**: System time advances via PIT ticks, and user keystrokes are asynchronously buffered and processed.

The KFS series at 42 demonstrates the inner mechanics of modern computing: how bare-metal instructions coordinate with silicon controllers, physical RAM, and CPU registers to provide the stable, protected execution environments we take for granted every day.

# Introduction :

Lorsqu'un ordinateur x86 est mis sous tension, il s'initialise en Mode Réel 16 bits — un environnement d'exécution quasiment identique à celui du processeur Intel 8086 de 1978. Le microprogramme de la carte mère (BIOS ou CSM UEFI) procède aux vérifications matérielles (POST), localise un support amorçable et charge le premier secteur de 512 octets en mémoire physique à l'adresse `0x7C00`. Écrire un système d'exploitation complet au sein d'un Master Boot Record (MBR) de 512 octets est une tâche notoirement fastidieuse et propice aux erreurs.

C'est ici qu'intervient la **Spécification Multiboot**, un standard conçu par la Free Software Foundation (FSF) et implémenté par les chargeurs d'amorçage modernes comme **GRUB** (*GRand Unified Bootloader*). Multiboot fait la passerelle entre l'initialisation matérielle et l'exécution du noyau : le bootloader bascule le CPU en Mode Protégé 32 bits, configure une segmentation plate, collecte la carte de mémoire physique du système et transmet le contrôle à notre exécutable noyau à un point d'entrée prédéterminé.

**KFS-1 (Kernel From Scratch 1)** constitue la porte d'entrée de l'architecture des systèmes d'exploitation à 42. Dans ce projet, nous nous affranchissons de la bibliothèque C standard (`libc`), des allocateurs de mémoire et des appels système pour bâtir un noyau bare-metal 32 bits en assembleur pur et C autonome (*freestanding*), équipé de son propre moteur d'affichage VGA.

---

# Objectifs du Projet :

L'objectif premier de KFS-1 est de concevoir un noyau x86 amorçable respectant la spécification Multiboot et pilotant directement le matériel sans système d'exploitation sous-jacent :

1. **Conformité Multiboot** : Intégrer un en-tête Multiboot valide au sein du binaire pour permettre à GRUB de l'identifier et de l'amorcer.
2. **Script d'Édition de Liens (Linker Script)** : Structurer un script ELF32 organisant les sections mémoire (`.text`, `.rodata`, `.data`, `.bss`) à partir de `0x00100000` (1 Mo), évitant la mémoire réservée du BIOS en deçà de 1 Mo.
3. **Amorçage en Assembleur** : Initialiser un pointeur de pile noyau (`ESP`), réinitialiser les drapeaux CPU, valider le nombre magique Multiboot et basculer vers le code C.
4. **Pilote Vidéo VGA Mode Texte** : Contrôler la mémoire vidéo mappée à l'adresse `0x000B8000` pour afficher des caractères, gérer les couleurs et positionner le curseur matériel.
5. **Gestion de Terminal** : Prendre en charge le retour à la ligne automatique, le défilement de l'écran (*scrolling*) dès la ligne 25 et les caractères de contrôle (`\n`, `\r`, `\t`, `\b`).
6. **Affichage Formaté Noyau (`printk`)** : Développer une fonction d'impression formatée prenant en charge les chaînes de caractères, entiers, nombres hexadécimaux et pointeurs.

# Architecture de la Séquence d'Amorçage :

La transition depuis le microprogramme jusqu'à l'exécution de notre noyau suit un pipeline matériel rigoureusement défini :

```
┌─────────────────┐
│   Mise sous     │  Vecteur de réinitialisation matériel (0xFFFFFFF0)
│  tension / POST │  Initialise les bus, contrôleurs de mémoire et périphériques
└────────┬────────┘
         │
         ▼
┌─────────────────┐
│ Bootloader GRUB │  Charge le binaire du noyau depuis l'ISO ou le disque
│  (Multiboot)    │  Bascule le CPU en Mode Protégé 32 bits (ligne A20 activée)
└────────┬────────┘  Transmet EAX = 0x2BADB002, EBX = pointeur multiboot_info
         │
         ▼
┌─────────────────┐
│ boot.s (_start) │  Initialise ESP avec un tampon de pile statique
│ Entrée Assembleur│  Efface EFLAGS, valide le nombre magique Multiboot
└────────┬────────┘
         │
         ▼
┌─────────────────┐
│   kmain.c       │  Initialise le tampon texte VGA à l'adresse 0xB8000
│   Exécution C   │  Active le curseur matériel, affiche la bannière via printk()
└─────────────────┘
```

# Déroulement du Projet :

## 1️⃣ L'En-tête Multiboot

Pour que GRUB reconnaisse notre binaire comme un noyau amorçable, l'exécutable doit contenir un **en-tête Multiboot** aligné sur 32 bits dans ses 8192 premiers octets. Cet en-tête exige trois champs 32 bits obligatoires :

* **Nombre Magique (`0x1BADB002`)** : Signature d'identification Multiboot.
* **Flags** : Masque de bits requérant des fonctionnalités spécifiques du bootloader (ex. : aligner les modules sur des pages, fournir la carte de mémoire).
* **Somme de Contrôle (Checksum)** : Valeur qui, additionnée à `magic + flags`, produit un résultat nul (`-(magic + flags)`).

```nasm
; boot.s - En-tête Multiboot et Point d'Entrée du Noyau
[BITS 32]

MB_ALIGN     equ 1 << 0                   ; Aligne les modules chargés sur des pages de 4 Ko
MB_MEMINFO   equ 1 << 1                   ; Fournit la carte mémoire au noyau
MB_FLAGS     equ MB_ALIGN | MB_MEMINFO    ; Drapeaux Multiboot
MB_MAGIC     equ 0x1BADB002               ; Constante magique Multiboot
MB_CHECKSUM  equ -(MB_MAGIC + MB_FLAGS)   ; Checksum: magic + flags + checksum = 0

section .multiboot
align 4
    dd MB_MAGIC
    dd MB_FLAGS
    dd MB_CHECKSUM
```

## 2️⃣ Script d'Édition de Liens & Organisation de la Mémoire

Les noyaux de systèmes d'exploitation ne doivent pas être chargés à l'adresse physique `0x00000000`. Le premier mégaoctet de RAM contient des structures de données critiques du Mode Réel, notamment la Table des Vecteurs d'Interruptions (IVT), la Zone de Données du BIOS (BDA) et des tampons matériels mappés en mémoire (comme le tampon vidéo VGA entre `0xA0000` et `0xBFFFF`).

Nous configurons notre script pour l'éditeur de liens GNU (`ld`) afin d'implanter le noyau à partir de `1 Mo` (`0x00100000`) :

```ld
/* linker.ld - Script d'Édition de Liens du Noyau */
ENTRY(_start)
OUTPUT_FORMAT(elf32-i386)
OUTPUT_ARCH(i386)

SECTIONS
{
    /* Le noyau est chargé à 1 Mo en mémoire physique */
    . = 0x00100000;

    /* L'en-tête Multiboot doit obligatoirement figurer dans les 8 premiers Ko */
    .text BLOCK(4K) : ALIGN(4K)
    {
        *(.multiboot)
        *(.text*)
    }

    /* Données en lecture seule (constantes, chaînes littérales) */
    .rodata BLOCK(4K) : ALIGN(4K)
    {
        *(.rodata*)
    }

    /* Données initialisées en lecture-écriture */
    .data BLOCK(4K) : ALIGN(4K)
    {
        *(.data*)
    }

    /* Données non initialisées (mises à zéro) et pile */
    .bss BLOCK(4K) : ALIGN(4K)
    {
        *(COMMON)
        *(.bss*)
    }

    kernel_end = .;
}
```

## 3️⃣ Bootstrap en Assembleur (`_start`)

Lorsque GRUB transfère l'exécution à `_start`, le processeur est en Mode Protégé 32 bits, les interruptions sont coupées et la pagination est inactive. Cependant, **aucun pointeur de pile C valide n'existe**. Comme les appels de fonctions C s'appuient sur `ESP` pour allouer les trames locales et empiler les adresses de retour, nous devons réserver un espace de pile dédié dans la section `.bss` et l'affecter à `ESP` avant tout appel en C :

```nasm
section .bss
align 16
stack_bottom:
    resb 16384                          ; Pile noyau de 16 Kio
stack_top:

section .text
global _start
extern kmain

_start:
    ; Initialisation du pointeur de pile
    mov esp, stack_top

    ; Réinitialisation du registre EFLAGS (efface DF, IF, etc.)
    push 0
    popf

    ; GRUB dépose le nombre magique (0x2BADB002) dans EAX et l'adresse multiboot_info dans EBX
    ; Nous les empilons comme arguments pour kmain(uint32_t magic, multiboot_info_t *mbi)
    push ebx
    push eax

    ; Appel du point d'entrée C du noyau
    call kmain

    ; En cas de retour imprévu de kmain, verrouillage dans une boucle d'arrêt
.halt:
    cli
    hlt
    jmp .halt
```

## 4️⃣ Pilote Vidéo VGA en Mode Texte

Les contrôleurs vidéo compatibles PC fournissent un mode texte de 80 colonnes par 25 lignes accessible via une zone de mémoire mappée à l'adresse physique `0x000B8000`.

### Structure d'une Case Écran
Chaque caractère à l'écran occupe **2 octets consécutifs** en mémoire vidéo :

```
 15              12 11              8 7                             0
┌──────────────────┬─────────────────┬───────────────────────────────┐
│ Couleur de Fond  │ Couleur du Texte│       Caractère ASCII         │
│     (4 bits)     │    (4 bits)     │            (8 bits)           │
└──────────────────┴─────────────────┴───────────────────────────────┘
```

Les 16 couleurs standard VGA sont définies ainsi :

| Code | Couleur | Code | Couleur |
|---|---|---|---|
| `0x0` | Noir | `0x8` | Gris foncé |
| `0x1` | Bleu | `0x9` | Bleu clair |
| `0x2` | Vert | `0xA` | Vert clair |
| `0x3` | Cyan | `0xB` | Cyan clair |
| `0x4` | Rouge | `0xC` | Rouge clair |
| `0x5` | Magenta | `0xD` | Rose |
| `0x6` | Marron | `0xE` | Jaune / Brun clair |
| `0x7` | Gris clair | `0xF` | Blanc |

### Implémentation du Pilote Vidéo

```c
/* vga.h - Pilote VGA en Mode Texte */
#ifndef VGA_H
#define VGA_H

#include <stdint.h>
#include <stddef.h>

#define VGA_WIDTH   80
#define VGA_HEIGHT  25
#define VGA_MEMORY  ((volatile uint16_t *)0x000B8000)

enum vga_color {
    VGA_COLOR_BLACK         = 0,
    VGA_COLOR_BLUE          = 1,
    VGA_COLOR_GREEN         = 2,
    VGA_COLOR_CYAN          = 3,
    VGA_COLOR_RED           = 4,
    VGA_COLOR_MAGENTA       = 5,
    VGA_COLOR_BROWN         = 6,
    VGA_COLOR_LIGHT_GREY    = 7,
    VGA_COLOR_DARK_GREY     = 8,
    VGA_COLOR_LIGHT_BLUE    = 9,
    VGA_COLOR_LIGHT_GREEN   = 10,
    VGA_COLOR_LIGHT_CYAN    = 11,
    VGA_COLOR_LIGHT_RED     = 12,
    VGA_COLOR_LIGHT_MAGENTA = 13,
    VGA_COLOR_LIGHT_BROWN   = 14,
    VGA_COLOR_WHITE         = 15,
};

static inline uint8_t vga_entry_color(enum vga_color fg, enum vga_color bg) {
    return fg | (bg << 4);
}

static inline uint16_t vga_entry(unsigned char uc, uint8_t color) {
    return (uint16_t)uc | ((uint16_t)color << 8);
}

void vga_init(void);
void vga_putc(char c);
void vga_puts(const char *str);
void vga_clear(void);
void vga_set_color(enum vga_color fg, enum vga_color bg);
void vga_set_cursor(size_t x, size_t y);

#endif
```

## 5️⃣ Ports d'E/S et Curseur Matériel

Sur l'architecture x86, la communication avec les périphériques matériels s'effectue à travers un espace d'adressage d'E/S dédié via les instructions assembleur `in` et `out` :

```c
/* io.h - Primitives d'E/S sur les Ports x86 */
static inline void outb(uint16_t port, uint8_t val) {
    __asm__ volatile ("outb %0, %1" : : "a"(val), "Nd"(port));
}

static inline uint8_t inb(uint16_t port) {
    uint8_t ret;
    __asm__ volatile ("inb %1, %0" : "=a"(ret) : "Nd"(port));
    return ret;
}
```

Le contrôleur CRT de la carte VGA communique via les ports `0x3D4` (registre d'index) et `0x3D5` (registre de données). La position du curseur clignotant est un décalage linéaire variant de `0` à `80 * 25 - 1` :

```c
void vga_set_cursor(size_t x, size_t y) {
    uint16_t pos = y * VGA_WIDTH + x;

    // Envoi de l'octet de poids fort au registre 0x0E
    outb(0x3D4, 0x0E);
    outb(0x3D5, (uint8_t)((pos >> 8) & 0xFF));

    // Envoi de l'octet de poids faible au registre 0x0F
    outb(0x3D4, 0x0F);
    outb(0x3D5, (uint8_t)(pos & 0xFF));
}
```

## 6️⃣ Défilement d'Écran et Caractères de Contrôle

Une console exploitable doit gérer les retours à la ligne (`\n`), les retours chariot (`\r`), les effacements arrières (`\b`), les tabulations (`\t`) et faire défiler l'écran vers le haut lorsque le curseur atteint la dernière ligne :

```c
static size_t term_row;
static size_t term_col;
static uint8_t term_color;

static void vga_scroll(void) {
    // Déplace les lignes 1..24 vers les lignes 0..23
    for (size_t y = 1; y < VGA_HEIGHT; y++) {
        for (size_t x = 0; x < VGA_WIDTH; x++) {
            VGA_MEMORY[(y - 1) * VGA_WIDTH + x] = VGA_MEMORY[y * VGA_WIDTH + x];
        }
    }
    // Efface la dernière ligne du bas
    uint16_t blank = vga_entry(' ', term_color);
    for (size_t x = 0; x < VGA_WIDTH; x++) {
        VGA_MEMORY[(VGA_HEIGHT - 1) * VGA_WIDTH + x] = blank;
    }
    term_row = VGA_HEIGHT - 1;
}

void vga_putc(char c) {
    if (c == '\n') {
        term_col = 0;
        term_row++;
    } else if (c == '\r') {
        term_col = 0;
    } else if (c == '\b') {
        if (term_col > 0) {
            term_col--;
            VGA_MEMORY[term_row * VGA_WIDTH + term_col] = vga_entry(' ', term_color);
        }
    } else if (c == '\t') {
        term_col = (term_col + 4) & ~3;
    } else {
        VGA_MEMORY[term_row * VGA_WIDTH + term_col] = vga_entry(c, term_color);
        term_col++;
    }

    if (term_col >= VGA_WIDTH) {
        term_col = 0;
        term_row++;
    }
    if (term_row >= VGA_HEIGHT) {
        vga_scroll();
    }
    vga_set_cursor(term_col, term_row);
}
```

## 7️⃣ Fonction d'Affichage Noyau `printk`

En l'absence de la fonction `printf` de la bibliothèque C, nous concevons un formateur variadique en nous appuyant sur les macros internes du compilateur `va_list`, `va_start` et `va_arg` :

```c
#include <stdarg.h>

void printk(const char *fmt, ...) {
    va_list args;
    va_start(args, fmt);

    for (const char *p = fmt; *p != '\0'; p++) {
        if (*p != '%') {
            vga_putc(*p);
            continue;
        }
        p++;
        switch (*p) {
            case 'c':
                vga_putc((char)va_arg(args, int));
                break;
            case 's': {
                const char *s = va_arg(args, const char *);
                vga_puts(s ? s : "(null)");
                break;
            }
            case 'd':
            case 'i':
                print_dec(va_arg(args, int32_t));
                break;
            case 'x':
                print_hex(va_arg(args, uint32_t));
                break;
            case 'p':
                vga_puts("0x");
                print_hex((uint32_t)va_arg(args, void *));
                break;
            case '%':
                vga_putc('%');
                break;
            default:
                vga_putc('%');
                vga_putc(*p);
                break;
        }
    }
    va_end(args);
}
```

## 8️⃣ Compilation et Exécution sous QEMU

Nous empaquetons le binaire ELF dans une image ISO avec `grub-mkrescue` et un fichier de configuration `grub.cfg` épuré :

```bash
# Arborescence
# isodir/
# └── boot/
#     ├── grub/
#     │   └── grub.cfg
#     └── kfs.bin

# grub.cfg
menuentry "42 KFS-1 Kernel" {
    multiboot /boot/kfs.bin
    boot
}
```

```bash
# Compilation avec les drapeaux freestanding de GCC
$ gcc -m32 -ffreestanding -fno-builtin -fno-stack-protector -nostdlib -Wall -Wextra -c kmain.c -o kmain.o
$ nasm -f elf32 boot.s -o boot.o
$ ld -m elf_i386 -T linker.ld -o kfs.bin boot.o kmain.o

# Création de l'ISO amorçable et test sous QEMU
$ mkdir -p isodir/boot/grub
$ cp kfs.bin isodir/boot/
$ cp grub.cfg isodir/boot/grub/
$ grub-mkrescue -o kfs.iso isodir
$ qemu-system-i386 -cdrom kfs.iso
```

# Points Clés & Perspectives :

KFS-1 pose les fondations indispensables du développement de systèmes d'exploitation. Nous sommes passés avec succès du chargeur d'amorçage GRUB au mode d'exécution 32 bits, avons conçu notre propre pilote matériel en manipulant directement les adresses de mémoire physique et les ports d'E/S, et établi une sortie de diagnostic autonome sans dépendre de la moindre ligne de code externe.

Cependant, notre processeur fonctionne encore sur les segments temporaires et rudimentaires mis en place par GRUB. Dans **KFS-2**, nous prendrons le contrôle intégral de la segmentation mémoire en bâtissant notre propre **Table Globale des Descripteurs (GDT)** et en implémentant un **dérouleur de pile noyau** pour inspecter l'exécution et diagnostiquer les plantages.

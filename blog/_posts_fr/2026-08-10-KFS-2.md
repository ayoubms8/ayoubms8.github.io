# Introduction :

En mode protégé x86 32 bits, le processeur garantit les privilèges d'accès à la mémoire à travers deux mécanismes matériels complémentaires : la **Segmentation** et la **Pagination**. Avant même que les systèmes d'exploitation modernes ne puissent activer la mémoire virtuelle et les tables de pages, le processeur exige impérativement que la segmentation soit initialisée.

Bien que GRUB démarre le noyau en mode protégé avec des sélecteurs de segments par défaut, un système d'exploitation ne peut pas se reposer sur les configurations du chargeur d'amorçage. Les segments du bootloader sont temporaires, n'opèrent aucune distinction entre les anneaux de privilège noyau et utilisateur, et peuvent résider dans des zones de mémoire susceptibles d'être écrasées.

Dans **KFS-2 (Kernel From Scratch 2)**, nous prenons le contrôle intégral de l'architecture mémoire du processeur en construisant notre propre **Table Globale des Descripteurs (GDT)**, installée à l'adresse physique `0x00000800`, et en développant un **inspecteur de pile noyau et shell de débogage** capable de dérouler les trames d'appels et d'examiner la mémoire en temps réel.

---

# Objectifs du Projet :

1. **Construire une GDT Complète** : Définir les segments de l'espace noyau (Ring 0) et de l'espace utilisateur (Ring 3), couvrant les segments de code, de données et de pile.
2. **Installation à Adresse Fixe** : Implanter la table GDT à l'adresse mémoire physique exacte `0x00000800` conformément au sujet de 42.
3. **Rechargement des Registres de Segments** : Charger le registre GDTR avec l'instruction `lgdt`, recharger `CS` via un saut lointain (*far jump*) en assembleur, et actualiser les registres de segments de données (`DS`, `ES`, `FS`, `GS`, `SS`).
4. **Analyse de la Trame de Pile Noyau** : Maîtriser l'organisation de la pile x86 structurée par les registres `EBP` et `ESP`.
5. **Déréférencement de Pile (Stack Unwinder) & Vidage Mémoire** : Implémenter une fonction de backtrace qui parcourt la chaîne des pointeurs de trame et affiche les adresses de retour des appelants.
6. **Shell de Diagnostic** : Fournir une interface interactive minimale prenant en charge des commandes telles que `stack`, `dump`, `reboot` et `halt`.

# Segmentation & GDT :

Sur l'architecture IA-32, les adresses manipulées par les instructions sont des **Adresses Logiques** (composées d'un Sélecteur de Segment et d'un Décalage / Offset). L'unité de segmentation matérielle traduit cette adresse logique en une **Adresse Linéaire** en ajoutant l'adresse de base du segment.

```
Adresse Logique : [ Sélecteur de Segment (16 bits) : Décalage (32 bits) ]
                         │
                         ▼
             ┌─────────────────────────┐
             │ Table Globale (GDT)     │
             ├─────────────────────────┤
             │ Descripteur [Index]     │ ──► Adresse de Base (32 bits) + Limite
             └─────────────────────────┘
                         │
                         ▼
Adresse Linéaire : [ Adresse de Base + Décalage ]
```

Chaque entrée de la GDT est un descripteur de **8 octets (64 bits)** encodant l'adresse de base, la limite, l'anneau de privilège et les attributs d'accès du segment :

```
 63          56 55 54 53 52 51    48 47          40 39        16 15            0
┌──────────────┬──┬──┬──┬──┬────────┬──────────────┬────────────┬──────────────┐
│  Base 31..24 │G │DB│0 │A │Lim19..16│ Octet Accès  │ Base 23..0 │  Limite 15..0│
└──────────────┴──┴──┴──┴──┴────────┴──────────────┴────────────┴──────────────┘
```

### Anatomie de l'Octet d'Accès (Bits 40–47)
* **P (Present)** : Bit 7. Doit valoir `1` pour les segments valides.
* **DPL (Descriptor Privilege Level)** : Bits 5–6. Ring 0 (`00b`) pour le noyau, Ring 3 (`11b`) pour l'espace utilisateur.
* **S (Descriptor Type)** : Bit 4. `1` pour les segments de code/données, `0` pour les segments système (TSS, LDT).
* **E (Executable)** : Bit 3. `1` pour le code, `0` pour les données et la pile.
* **DC (Direction / Conforming)** : Bit 2. Pour les données : `0` croît vers le haut, `1` vers le bas. Pour le code : `0` non conforme.
* **RW (Readable / Writable)** : Bit 1. Pour le code : lecture autorisée (`1`). Pour les données : écriture autorisée (`1`).
* **A (Accessed)** : Bit 0. Initialisé à `0`, positionné à `1` par le CPU lors d'un accès.

### Granularité & Drapeaux (Bits 52–55)
* **G (Granularity)** : Bit 55. Si `1`, la limite est multipliée par des pages de 4 Kio (permet d'adresser jusqu'à 4 Gio).
* **DB (Size Flag)** : Bit 54. `1` pour les opérations en mode protégé 32 bits, `0` pour le 16 bits.

# Organisation de la GDT dans KFS-2 :

Nous configurons 7 entrées de descripteurs :

| Index | Décalage | Nom du Descripteur | DPL | Octet d'Accès | Drapeaux | Base | Limite |
|---|---|---|---|---|---|---|---|
| 0 | `0x00` | Descripteur Nul | 0 | `0x00` | `0x0` | `0x00000000` | `0x00000` |
| 1 | `0x08` | Segment Code Noyau | Ring 0 | `0x9A` | `0xC` | `0x00000000` | `0xFFFFF` (4 Go) |
| 2 | `0x10` | Segment Données Noyau | Ring 0 | `0x92` | `0xC` | `0x00000000` | `0xFFFFF` (4 Go) |
| 3 | `0x18` | Segment Pile Noyau | Ring 0 | `0x92` | `0xC` | `0x00000000` | `0xFFFFF` (4 Go) |
| 4 | `0x20` | Segment Code Utilisateur | Ring 3 | `0xFA` | `0xC` | `0x00000000` | `0xFFFFF` (4 Go) |
| 5 | `0x28` | Segment Données Utilisateur | Ring 3 | `0xF2` | `0xC` | `0x00000000` | `0xFFFFF` (4 Go) |
| 6 | `0x30` | Segment Pile Utilisateur | Ring 3 | `0xF2` | `0xC` | `0x00000000` | `0xFFFFF` (4 Go) |

# Déroulement du Projet :

## :one: Définition des Structures de la GDT en C

```c
/* gdt.h - En-tête de la Table Globale des Descripteurs */
#ifndef GDT_H
#define GDT_H

#include <stdint.h>

#define GDT_TARGET_ADDR 0x00000800
#define GDT_ENTRY_COUNT 7

struct gdt_entry {
    uint16_t limit_low;     // 16 bits de poids faible de la limite
    uint16_t base_low;      // 16 bits de poids faible de la base
    uint8_t  base_middle;   // 8 bits suivants de la base
    uint8_t  access;        // Octet d'accès
    uint8_t  granularity;   // Granularité et 4 bits supérieurs de la limite
    uint8_t  base_high;     // 8 derniers bits de la base
} __attribute__((packed));

struct gdt_ptr {
    uint16_t limit;         // Taille de la table GDT - 1
    uint32_t base;          // Adresse de la première entrée GDT
} __attribute__((packed));

void gdt_init(void);

#endif
```

## :two: Installation de la GDT à l'adresse `0x00000800`

Le sujet KFS-2 exige que la GDT soit écrite directement à l'adresse physique `0x00000800`. Nous transtypons directement ce pointeur mémoire :

```c
/* gdt.c - Implémentation de la Table Globale des Descripteurs */
#include "gdt.h"
#include <string.h>

extern void gdt_flush(uint32_t gdt_ptr_addr);

static void gdt_set_gate(int32_t num, uint32_t base, uint32_t limit, uint8_t access, uint8_t gran) {
    struct gdt_entry *gdt = (struct gdt_entry *)GDT_TARGET_ADDR;

    gdt[num].base_low    = (base & 0xFFFF);
    gdt[num].base_middle = (base >> 16) & 0xFF;
    gdt[num].base_high   = (base >> 24) & 0xFF;

    gdt[num].limit_low   = (limit & 0xFFFF);
    gdt[num].granularity = ((limit >> 16) & 0x0F) | (gran & 0xF0);
    gdt[num].access      = access;
}

void gdt_init(void) {
    struct gdt_ptr gp;

    gp.limit = (sizeof(struct gdt_entry) * GDT_ENTRY_COUNT) - 1;
    gp.base  = GDT_TARGET_ADDR;

    // 0x00: Descripteur nul
    gdt_set_gate(0, 0, 0, 0, 0);

    // 0x08: Segment Code Noyau (Ring 0, RX)
    gdt_set_gate(1, 0, 0xFFFFFFFF, 0x9A, 0xCF);

    // 0x10: Segment Données Noyau (Ring 0, RW)
    gdt_set_gate(2, 0, 0xFFFFFFFF, 0x92, 0xCF);

    // 0x18: Segment Pile Noyau (Ring 0, RW)
    gdt_set_gate(3, 0, 0xFFFFFFFF, 0x92, 0xCF);

    // 0x20: Segment Code Utilisateur (Ring 3, RX)
    gdt_set_gate(4, 0, 0xFFFFFFFF, 0xFA, 0xCF);

    // 0x28: Segment Données Utilisateur (Ring 3, RW)
    gdt_set_gate(5, 0, 0xFFFFFFFF, 0xF2, 0xCF);

    // 0x30: Segment Pile Utilisateur (Ring 3, RW)
    gdt_set_gate(6, 0, 0xFFFFFFFF, 0xF2, 0xCF);

    // Rechargement des registres de segments du processeur
    gdt_flush((uint32_t)&gp);
}
```

## :three: Rechargement des Segments en Assembleur

L'exécution de l'instruction `lgdt` indique au processeur l'emplacement de la table, mais ne met **pas** à jour les caches de descripteurs cachés dans les registres du CPU :

* Le registre `CS` (Code Segment) ne peut être rechargé avec `mov`. Il doit impérativement être rafraîchi par un **saut lointain** (`jmp 0x08:.reload_cs`).
* `DS`, `ES`, `SS`, `FS` et `GS` sont mis à jour en déplaçant le sélecteur `0x10` dans chaque registre.

```nasm
; gdt_flush.s - Routine d'actualisation des sélecteurs de segments
[BITS 32]
global gdt_flush

gdt_flush:
    mov eax, [esp + 4]      ; Récupère le pointeur vers gdt_ptr passé en argument
    lgdt [eax]              ; Charge le pointeur GDT dans le registre GDTR du CPU

    ; Saut lointain pour vider le pipeline et charger CS avec 0x08 (Code Noyau)
    jmp 0x08:.reload_cs

.reload_cs:
    ; Recharge les sélecteurs de données avec 0x10 (Données Noyau)
    mov ax, 0x10
    mov ds, ax
    mov es, ax
    mov fs, ax
    mov gs, ax
    mov ss, ax              ; Configure le sélecteur de segment de pile

    ret
```

## :four: La Pile d'Appel x86 & le Pointeur de Trame (Frame Pointer)

Lorsqu'une fonction C standard est appelée sur x86 32 bits, le compilateur structure une trame de pile à l'aide du registre de base (`EBP`) :

```
Adresses Hautes
┌───────────────────────────┐
│ Argument 2                │ [EBP + 12]
├───────────────────────────┤
│ Argument 1                │ [EBP + 8]
├───────────────────────────┤
│ Adresse de Retour (EIP)   │ [EBP + 4]  <-- Empilée automatiquement par CALL
├───────────────────────────┤
│ Ancien EBP Sauvegardé     │ [EBP]      <-- Empilé par le prologue (push ebp)
├───────────────────────────┤
│ Variables Locales         │ [EBP - 4]
│                           │ [EBP - 8]
└───────────────────────────┘
Adresses Basses (ESP pointe au sommet de la pile)
```

Le prologue de toute fonction standard s'exécute ainsi :
```nasm
push ebp
mov ebp, esp
sub esp, N
```

Puisque `EBP` pointe directement vers l'ancien `EBP` de la fonction appelante, les trames de pile forment une **liste chaînée** remontant jusqu'à `_start`. Le mot mémoire situé immédiatement au-dessus de `[EBP]` (`[EBP + 4]`) contient l'adresse de retour de l'appelant !

## :five: Implémentation du Dérouleur de Pile (Stack Unwinder)

Pour afficher un backtrace d'exécution, nous lisons l'adresse courante d'`EBP` et traversons la chaîne :

```c
/* stack.c - Dérouleur de Pile Noyau */
#include "printk.h"
#include <stdint.h>

struct stack_frame {
    struct stack_frame *next;
    uint32_t return_address;
};

void kernel_backtrace(uint32_t max_frames) {
    struct stack_frame *frame;

    // Lecture du registre EBP actuel via assembleur inline
    __asm__ volatile ("mov %%ebp, %0" : "=r"(frame));

    printk("\n=== [ TRACE DE LA PILE NOYAU (BACKTRACE) ] ===\n");
    printk("Trame        Base Pointer (EBP)   Adresse Retour (EIP)\n");
    printk("---------------------------------------------------\n");

    uint32_t depth = 0;
    while (frame != 0 && depth < max_frames) {
        // Vérification de validité : EBP doit être aligné sur 4 octets et dans une plage plausible
        if (((uint32_t)frame & 0x3) != 0 || (uint32_t)frame < 0x00100000) {
            break;
        }

        printk("#%-2d          0x%x           0x%x\n", depth, (uint32_t)frame, frame->return_address);

        frame = frame->next;
        depth++;
    }
    printk("===================================================\n\n");
}
```

## :six: Vidage Hexadécimal de la Mémoire et de la Pile

Un inspecteur système doit pouvoir afficher la mémoire brute sous forme combinée hexadécimale et ASCII :

```c
void dump_memory(const void *addr, size_t size) {
    const uint8_t *ptr = (const uint8_t *)addr;
    char ascii[17];
    ascii[16] = '\0';

    printk("Vidage de %d octets à l'adresse %p :\n", size, addr);

    for (size_t i = 0; i < size; i++) {
        if (i % 16 == 0) {
            printk("%p: ", &ptr[i]);
        }

        printk("%02x ", ptr[i]);
        ascii[i % 16] = (ptr[i] >= 32 && ptr[i] <= 126) ? (char)ptr[i] : '.';

        if ((i + 1) % 16 == 0 || i + 1 == size) {
            // Complète avec des espaces si la dernière ligne est incomplète
            if (i + 1 == size && (i + 1) % 16 != 0) {
                for (size_t pad = 0; pad < 16 - ((i + 1) % 16); pad++) {
                    printk("   ");
                }
            }
            printk(" |%s|\n", ascii);
            memset(ascii, 0, sizeof(ascii));
        }
    }
}
```

## :seven: Shell Interactif de Diagnostic

Nous relions une boucle de commande simple permettant d'inspecter la mémoire et de réinitialiser le CPU :

```c
void cmd_reboot(void) {
    printk("Redémarrage du système via le contrôleur clavier 8042...\n");
    // Envoi de la commande de réinitialisation en écrivant 0xFE sur le port 0x64
    uint8_t temp;
    do {
        temp = inb(0x64);
        if (temp & 1)
            (void)inb(0x60);
    } while (temp & 2);

    outb(0x64, 0xFE);

    // Repli : Provoquer un Triple Fault en chargeant une IDT nulle
    struct { uint16_t limit; uint32_t base; } __attribute__((packed)) null_idtr = { 0, 0 };
    __asm__ volatile ("lidt %0; int3" : : "m"(null_idtr));
}

void cmd_halt(void) {
    printk("Arrêt du processeur...\n");
    __asm__ volatile ("cli; hlt");
}
```

# Points Clés & Ce qui suit :

Dans KFS-2, nous avons pris le contrôle complet de la segmentation matérielle :
1. La GDT est installée avec succès à l'adresse physique `0x00000800`.
2. Les segments sont compartimentés entre les zones Ring 0 (noyau) et Ring 3 (utilisateur).
3. L'architecture des trames de pile (`EBP`/`ESP`) permet un débogage dynamique et l'analyse post-mortem de la mémoire.

Bien que la segmentation découpe la mémoire en blocs logiques, elle ne propose pas de protection granulaire par page ni d'isolation entre processus indépendants. Dans **KFS-3**, nous aborderons la **Pagination à Deux Niveaux et la Mémoire Virtuelle**.

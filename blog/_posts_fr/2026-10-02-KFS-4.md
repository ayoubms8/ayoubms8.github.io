# Introduction :

Dans les étapes précédentes de KFS, notre noyau fonctionnait entièrement au sein d'une boucle d'interrogation synchrone (*polling*). Lorsque notre shell de diagnostic devait vérifier si une touche avait été pressée, il devait interroger continuellement les ports d'E/S matériels dans une boucle CPU serrée — gaspillant des cycles processeur précieux et rendant le véritable multitâche impossible.

Pour concevoir un système d'exploitation réactif, les périphériques matériels doivent pouvoir signaler le processeur de manière asynchrone dès qu'un événement survient. Simultanément, le processeur doit être capable d'intercepter les exceptions internes synchrones — telles qu'une division par zéro ou un défaut de page (*page fault*) — et dévier l'exécution vers un gestionnaire du système d'exploitation au lieu de bloquer ou faire planter la machine physique.

Dans **KFS-4 (Kernel From Scratch 4)**, nous établissons l'épine dorsale événementielle de notre système d'exploitation :
* Construction de la **Table des Descripteurs d'Interruptions (IDT)** avec l'ensemble des 256 portes (*gates*).
* Prise en charge des exceptions CPU Intel (vecteurs 0 à 31) avec des stubs de trame de pile (*stack frame*) uniformes.
* Remappage du **Double Contrôleur d'Interruptions Programmable (PIC 8259)** pour résoudre le conflit historique de vecteurs de l'architecture PC-AT.
* Configuration du **Timer d'Intervalle Programmable (PIT)** sur l'IRQ0 pour générer les ticks d'horloge système.
* Développement d'un **pilote clavier PS/2** entièrement géré par interruptions sur l'IRQ1 avec traduction des scancodes et tampon circulaire d'entrée.
* Intégration d'un shell noyau interactif entièrement piloté par les interruptions matérielles.

# Architecture des Interruptions x86 :

Sur l'architecture x86, les interruptions se divisent en deux catégories distinctes :

1. **Exceptions Synchrones (Internes)** : Générées directement par le processeur lors de l'exécution d'une instruction (ex. : `#DE` Division par zéro, `#GP` Faute de Protection Générale, `#PF` Défaut de Page).
2. **Interruptions Asynchrones (Externes / Matérielles)** : Générées par les périphériques externes (claviers, horloges, contrôleurs de disque, cartes réseau) et envoyées au CPU via les lignes du contrôleur d'interruptions (broche `INTR`).

```
Périphérique Matériel (Clavier / Timer)
                │
                ▼
┌───────────────────────────────┐
│  Double PIC 8259 (Maître/Esclave) │
└───────────────┬───────────────┘
                │  Ligne IRQ déclenchée -> convertie en vecteur (ex. : 33)
                ▼
┌───────────────────────────────┐
│     Flux d'Exécution CPU      │
│  - Suspend le code en cours   │
│  - Empile EFLAGS, CS, EIP     │
│  - Lit l'entrée IDT[33]       │
└───────────────┬───────────────┘
                │
                ▼
┌───────────────────────────────┐
│   Stub ISR (Assembleur)       │  Sauvegarde les registres (pusha), charge le DS noyau
└───────────────┬───────────────┘
                │
                ▼
┌───────────────────────────────┐
│  Dispatcher d'Interruption C  │  Appelle keyboard_handler(), envoie le signal EOI au PIC
└───────────────┬───────────────┘
                │
                ▼
┌───────────────────────────────┐
│   Instruction IRET            │  Restaure les registres, retour vers utilisateur/noyau
└───────────────────────────────┘
```

# Le Descripteur de Porte IDT :

La **Table des Descripteurs d'Interruptions (IDT)** comporte 256 entrées. Chaque entrée est une structure de 8 octets définissant l'adresse cible où l'exécution doit sauter lorsqu'un vecteur d'interruption est déclenché :

```
 63                                48 47  46 45 44 43 40 39       32 31               16 15                0
┌────────────────────────────────────┬───┬─────┬──┬─────┬───────────┬───────────────────┬───────────────────┐
│       Offset Haut (Bits 16..31)    │ P │ DPL │0 │Type │  Réservé  │ Sélecteur Segment │ Offset Bas (0..15)│
└────────────────────────────────────┴───┴─────┴──┴─────┴───────────┴───────────────────┴───────────────────┘
```

* **Offset (Bits 0..15 et 48..63)** : Adresse linéaire 32 bits de la routine de service d'interruption (ISR).
* **Sélecteur de Segment (Bits 16..31)** : Sélecteur de segment de code dans la GDT (`0x08` pour le code noyau).
* **Type (Bits 40..43)** : `0xE` (1110b) spécifie une porte d'interruption 32 bits (qui efface automatiquement le flag `IF` pour empêcher les interruptions imbriquées).
* **DPL (Bits 45..46)** : Niveau de privilège requis pour invoquer l'interruption via l'instruction logicielle `int` (`0` pour les exceptions noyau, `3` pour les appels système).
* **P (Present, Bit 47)** : Doit valoir `1` pour que la porte soit active.

## 2️⃣ Trames de Pile d'Exceptions & Stubs ISR en Assembleur

Lorsqu'une exception survient, le processeur empile automatiquement `EFLAGS`, `CS` et `EIP` sur la pile. Pour certaines exceptions (comme `#GP` 13 et `#PF` 14), le processeur **empile également un code d'erreur**. Pour d'autres (comme `#DE` 0 ou `#BP` 3), **aucun code d'erreur n'est empilé**.

Afin de transmettre une structure de registres uniforme à notre répartiteur C, nous empilons un code d'erreur fictif `0` pour les exceptions qui n'en fournissent pas :

```nasm
; isr.s - Stubs des Routines de Service d'Interruption
[BITS 32]

%macro ISR_NOERRCODE 1
global isr%1
isr%1:
    push 0                  ; Empile un code d'erreur fictif
    push %1                 ; Empile le numéro de vecteur d'interruption
    jmp isr_common_stub
%endmacro

%macro ISR_ERRCODE 1
global isr%1
isr%1:
    push %1                 ; Numéro de vecteur (le CPU a déjà empilé le code d'erreur)
    jmp isr_common_stub
%endmacro

; Définition des Exceptions CPU 0..31
ISR_NOERRCODE 0   ; 0: Division par zéro
ISR_NOERRCODE 1   ; 1: Debug
ISR_NOERRCODE 2   ; 2: Interruption non masquable (NMI)
ISR_NOERRCODE 3   ; 3: Point d'arrêt (Breakpoint)
ISR_NOERRCODE 4   ; 4: Dépassement de capacité (Overflow)
ISR_NOERRCODE 5   ; 5: Plage dépassée (Bound Range Exceeded)
ISR_NOERRCODE 6   ; 6: Opcode invalide
ISR_NOERRCODE 7   ; 7: Périphérique non disponible
ISR_ERRCODE   8   ; 8: Double faute
ISR_NOERRCODE 9   ; 9: Dépassement de segment coprocesseur
ISR_ERRCODE   10  ; 10: TSS invalide
ISR_ERRCODE   11  ; 11: Segment non présent
ISR_ERRCODE   12  ; 12: Faute de segment de pile
ISR_ERRCODE   13  ; 13: Faute de protection générale (#GP)
ISR_ERRCODE   14  ; 14: Défaut de page (#PF)
ISR_NOERRCODE 15  ; 15: Réservé
ISR_NOERRCODE 16  ; 16: Erreur FPU x87
ISR_ERRCODE   17  ; 17: Vérification d'alignement
ISR_NOERRCODE 18  ; 18: Vérification machine (Machine Check)
ISR_NOERRCODE 19  ; 19: Exception SIMD à virgule flottante
; ... jusqu'à 31

extern isr_handler

isr_common_stub:
    pusha                   ; Empile EDI, ESI, EBP, ESP, EBX, EDX, ECX, EAX

    mov ax, ds
    push eax                ; Sauvegarde le descripteur de segment de données d'origine

    mov ax, 0x10            ; Charge le segment de données noyau
    mov ds, ax
    mov es, ax
    mov fs, ax
    mov gs, ax

    push esp                ; Transmet le pointeur vers la trame de pile (registers_t *)
    call isr_handler
    add esp, 4              ; Nettoie le paramètre passé sur la pile

    pop eax                 ; Restaure le segment de données d'origine
    mov ds, ax
    mov es, ax
    mov fs, ax
    mov gs, ax

    popa                    ; Restaure les registres généraux
    add esp, 8              ; Supprime le code d'erreur et le numéro d'interruption de la pile
    iret                    ; Restaure CS, EIP, EFLAGS (et SS/ESP en cas de changement de privilège)
```

## 3️⃣ Remappage du Double PIC 8259

L'architecture IBM PC achemine les interruptions matérielles à travers deux contrôleurs PIC 8259 montés en cascade :
* **PIC Maître** : Connecté à la broche `INTR` du processeur, gère les IRQ 0..7 (Ports `0x20` / `0x21`).
* **PIC Esclave** : Connecté en cascade sur l'IRQ2 du Maître, gère les IRQ 8..15 (Ports `0xA0` / `0xA1`).

### Le Conflit Architectural
Par défaut, le BIOS IBM configure le PIC Maître pour déclencher les vecteurs d'interruption **`0x08`–`0x0F`**. Or, en Mode Protégé Intel 32 bits, les vecteurs `0x08`–`0x0F` sont réservés aux exceptions CPU (par exemple, le vecteur `0x08` correspond à la Double Faute `#DF`) ! Si le timer émet une interruption sur l'IRQ0, le processeur interprète cela comme une Double Faute et panique immédiatement.

Nous résolvons ce conflit en émettant les **mots d'initialisation ICW1–ICW4** pour remapper les deux PICs :
* PIC Maître remappé vers les vecteurs `32..39` (`0x20`–`0x27`).
* PIC Esclave remappé vers les vecteurs `40..47` (`0x28`–`0x2F`).

```c
/* pic.c - Remappage du PIC 8259 */
#include "io.h"

#define PIC1_COMMAND  0x20
#define PIC1_DATA     0x21
#define PIC2_COMMAND  0xA0
#define PIC2_DATA     0xA1

#define ICW1_INIT     0x10
#define ICW1_ICW4     0x01
#define ICW4_8086     0x01
#define PIC_EOI       0x20

void pic_remap(int offset1, int offset2) {
    uint8_t a1 = inb(PIC1_DATA); // Sauvegarde des masques d'interruption actuels
    uint8_t a2 = inb(PIC2_DATA);

    // ICW1: Démarrage de la séquence d'initialisation en mode cascade
    outb(PIC1_COMMAND, ICW1_INIT | ICW1_ICW4);
    io_wait();
    outb(PIC2_COMMAND, ICW1_INIT | ICW1_ICW4);
    io_wait();

    // ICW2: Décalage des vecteurs d'interruption
    outb(PIC1_DATA, offset1); // Décalage Maître : 32 (0x20)
    io_wait();
    outb(PIC2_DATA, offset2); // Décalage Esclave : 40 (0x28)
    io_wait();

    // ICW3: Indique au Maître que l'Esclave est connecté sur l'IRQ2 (0000 0100b = 4)
    outb(PIC1_DATA, 0x04);
    io_wait();
    // Indique à l'Esclave son identité de cascade (2)
    outb(PIC2_DATA, 0x02);
    io_wait();

    // ICW4: Utilisation du mode 8086/88
    outb(PIC1_DATA, ICW4_8086);
    io_wait();
    outb(PIC2_DATA, ICW4_8086);
    io_wait();

    // Restauration des masques sauvegardés
    outb(PIC1_DATA, a1);
    outb(PIC2_DATA, a2);
}

void pic_send_eoi(uint8_t irq) {
    if (irq >= 8) {
        outb(PIC2_COMMAND, PIC_EOI); // Envoi de l'EOI à l'Esclave
    }
    outb(PIC1_COMMAND, PIC_EOI);     // Envoi de l'EOI au Maître
}
```

## 4️⃣ Pilote du Timer d'Intervalle Programmable (PIT)

Le PIT 8254 oscille à une fréquence de base de `1,193182 MHz`. En programmant le diviseur de son canal 0 (port `0x40`), nous générons des interruptions d'horloge régulières et périodiques sur l'IRQ0 :

```c
/* pit.c - Pilote de Timer */
#define PIT_FREQUENCY_HZ 100
#define PIT_BASE_CLOCK   1193182

static volatile uint32_t timer_ticks = 0;

void pit_init(uint32_t frequency) {
    uint32_t divisor = PIT_BASE_CLOCK / frequency;

    // Octet de commande : Canal 0, mode d'accès lobyte/hibyte, onde carrée
    outb(0x43, 0x36);
    outb(0x40, (uint8_t)(divisor & 0xFF));
    outb(0x40, (uint8_t)((divisor >> 8) & 0xFF));

    register_interrupt_handler(32, pit_handler);
}

void pit_handler(registers_t *regs) {
    timer_ticks++;
    pic_send_eoi(0);
}
```

## 5️⃣ Pilote Clavier PS/2 (IRQ1)

Lorsqu'une touche est pressée ou relâchée sur un clavier PS/2 standard, le contrôleur clavier lève l'**IRQ1** (vecteur 33) et dépose un octet (**scancode**) dans le port d'E/S `0x60`.

Dans le **Scancode Set 1** :
* **Make Code (Touche Pressée)** : Valeurs comprises entre `0x01` et `0x58`.
* **Break Code (Touche Relâchée)** : Make code dont le bit 7 est activé (`scancode | 0x80`). Par exemple, l'appui sur Maj Gauche produit `0x2A`, son relâchement produit `0xAA`.

```c
/* keyboard.c - Pilote de Clavier PS/2 */
#include "keyboard.h"
#include "pic.h"
#include "io.h"

static int shift_active = 0;
static int caps_lock = 0;
static int ctrl_active = 0;

static const char kbd_us[128] = {
    0,  27, '1', '2', '3', '4', '5', '6', '7', '8', '9', '0', '-', '=', '\b',
  '\t', 'q', 'w', 'e', 'r', 't', 'y', 'u', 'i', 'o', 'p', '[', ']', '\n',
    0,  'a', 's', 'd', 'f', 'g', 'h', 'j', 'k', 'l', ';', '\'', '`',
    0, '\\', 'z', 'x', 'c', 'v', 'b', 'n', 'm', ',', '.', '/',   0,
  '*',   0, ' '
};

static const char kbd_us_shift[128] = {
    0,  27, '!', '@', '#', '$', '%', '^', '&', '*', '(', ')', '_', '+', '\b',
  '\t', 'Q', 'W', 'E', 'R', 'T', 'Y', 'U', 'I', 'O', 'P', '{', '}', '\n',
    0,  'A', 'S', 'D', 'F', 'G', 'H', 'J', 'K', 'L', ':', '\"', '~',
    0, '|', 'Z', 'X', 'C', 'V', 'B', 'N', 'M', '<', '>', '?',   0,
  '*',   0, ' '
};

void keyboard_handler(registers_t *regs) {
    uint8_t scancode = inb(0x60);

    // Vérifie si la touche est relâchée (break code)
    if (scancode & 0x80) {
        uint8_t released = scancode & ~0x80;
        if (released == 0x2A || released == 0x36) { // Maj Gauche / Droite
            shift_active = 0;
        } else if (released == 0x1D) {              // Ctrl
            ctrl_active = 0;
        }
    } else {
        // Touche pressée (make code)
        if (scancode == 0x2A || scancode == 0x36) {
            shift_active = 1;
        } else if (scancode == 0x3A) {              // Bascule Verr Maj (Caps Lock)
            caps_lock = !caps_lock;
        } else if (scancode == 0x1D) {
            ctrl_active = 1;
        } else {
            char c = (shift_active ^ caps_lock) ? kbd_us_shift[scancode] : kbd_us[scancode];
            if (c) {
                keyboard_enqueue_char(c);
            }
        }
    }

    pic_send_eoi(1);
}
```

## 6️⃣ Tampon Circulaire d'Entrée & Intégration du Shell

Pour découpler la latence de traitement des interruptions de l'affichage terminal, les frappes entrantes sont poussées dans un tampon circulaire (*ring buffer*) :

```c
#define KBD_BUFFER_SIZE 256
static char kbd_ring_buffer[KBD_BUFFER_SIZE];
static volatile uint32_t kbd_head = 0;
static volatile uint32_t kbd_tail = 0;

void keyboard_enqueue_char(char c) {
    uint32_t next = (kbd_head + 1) % KBD_BUFFER_SIZE;
    if (next != kbd_tail) { // Tampon non plein
        kbd_ring_buffer[kbd_head] = c;
        kbd_head = next;
    }
}

char kbd_getchar(void) {
    while (kbd_head == kbd_tail) {
        // Met en pause le processeur jusqu'à la prochaine interruption matérielle
        __asm__ volatile ("hlt");
    }
    char c = kbd_ring_buffer[kbd_tail];
    kbd_tail = (kbd_tail + 1) % KBD_BUFFER_SIZE;
    return c;
}
```

Nous disposons à présent d'un shell interactif réactif avec écho des caractères en temps réel. Nous ajoutons des commandes pour tester les exceptions CPU en toute sécurité :

* `divzero` : Exécute une instruction inline `div %0` avec un diviseur nul pour démontrer que le vecteur intercepte bien `#DE` et affiche les registres.
* `pagefault` : Déréférence l'adresse `0xDEADBEEF` pour lever le vecteur `#PF` 14 et valider la journalisation du registre `CR2`.
* `ticks` : Affiche le décompte des ticks système générés par l'IRQ0 du PIT.

```c
void cmd_test_divzero(void) {
    printk("Déclenchement intentionnel d'une Division par Zéro (#DE)...\n");
    volatile int a = 42;
    volatile int b = 0;
    volatile int c = a / b;
    (void)c;
}
```

# Points Clés & Enseignements :

Avec l'achèvement de KFS-4, notre noyau franchit l'étape décisive entre un simple démonstrateur statique et un véritable système d'exploitation interactif et piloté par les interruptions :
1. **Gestion de l'IDT & des ISR** : Les 32 exceptions CPU Intel sont interceptées proprement avec capture de l'état des registres et traces de pile.
2. **Contrôle du PIC** : Les interruptions matérielles des périphériques externes sont réalignées sans entrer en collision avec l'architecture du mode protégé.
3. **Timer & Clavier** : L'horloge système progresse via les ticks du PIT, et les frappes clavier sont bufferisées et traitées de manière asynchrone.

La série KFS à 42 dévoile les mécanismes intimes de l'informatique moderne : comment les instructions au niveau bare-metal s'articulent avec les contrôleurs matériels, la mémoire physique et les registres CPU pour fournir les environnements protégés et stables que nous utilisons au quotidien.
